# UI96：英雄条件配置的本地导入／导出

新局和新技能测试仍然清空当前条件，使用服务端默认规则。只有玩家手动点击导入，才在当前局应用备份；结束当前局也会清除尚未应用的导入意图。

## 使用

1. 进入技能调试，正常编辑各英雄条件。服务端确认成功的配置按英雄名称收集到本机，切换英雄不会清除之前收集的配置。
2. 打开「技能调试 → 条件配置：导入／导出」，点击「导出所有已保存英雄」。点击文本框，Ctrl+A、Ctrl+C，将文本粘贴到本地 `.json` 文件保存。
3. 开始新局或新的技能测试后，再打开此面板，将备份文件的完整内容粘贴进文本框，点击「导入并覆盖同名英雄」。也可先导出本机已有配置，再点击导入，以手动复用本机配置。
4. 导入只覆盖备份内的同名英雄，保留其他英雄的备份。当前局中的英雄在准备阶段应用；缺少配置中技能或装备时显示等待提示，补齐后继续应用。未在当前局出现的英雄只保留备份，不会生成英雄。

备份包括规则顺序、启用状态、动作、使用条件、目标条件与优先级、接近／移动／蓄力等规则设置。不保存英雄等级、天赋、装备物品、金币、进度和敌人参数。装备规则包含装备名称和条件，导入不会赠送装备。新局必须重新手动导入。

## 实现边界

- `rule_library.js` 使用 Panorama LocalStorage 的 `dota2_rpg_rule_library_v1` 键保存本机配置集合。JSON 格式为 `format: dota2_rpg_rule_library`、`version: 1` 和 `heroes` 映射；文本备份可以复制到其他电脑。
- 使用英雄名称和技能／物品实际名称，不保存上局的实体索引。导入仍通过现有 `rpg_update_rule` 逐条校验，以当前英雄实体应用。地图限定目标、特定队友等引用须符合当前场景；拒绝原因显示在原有条件同步提示中。
- 当前行尚未确认或任一行被拒绝时，不将该英雄的新草稿替换进备份；导出不包含未确认草稿。存在尚未返回的规则请求时拒绝导入，避免回执覆盖导入配置。
- JSON 先完整检查，再合并并写入存储。错误格式、未来版本、非法对象键、过大文本和超限规则不会部分覆盖配置。上限为 200 名英雄、每名 32 条规则、2 MiB JSON。
- 导入文件校验与本地写入是整体操作；服务端仍按现有协议逐行确认，不能承诺整组规则在服务端原子生效。部分规则拒绝时应依据界面提示调整，成功的行可能已经应用。
- 本地存储不可用时显示错误；已确认编辑可暂存在当前界面内供导出，导入不会宣称已成功保存。自动读取本机集合仅用于导出，不会自动应用到新局。

## 验证

新增 `rule-library.test.js`、`rule-library-hud.test.js`，扩展实际调试 XML 的双语交互测试，覆盖跨英雄备份、读盘、显式导入、百分比往返、当前实体绑定、新局默认条件与导入意图清除、战斗阶段延后、缺装备延后、乱序回执、失败保护、删除失败行、原子格式校验和存储故障。

使用 LuaJIT 运行 `scripts/test-all.py`。完整结果保存在 `tests/results/reliability-regression.json`。默认 Lua 5.4 不兼容项目旧测试中的 Lua 5.1 API，需设置 `LUA_BIN` 指向 LuaJIT。

当前环境的默认 Dota 安装路径不存在，`scripts/install-addon.ps1 -Compile` 在安装前退出；尚未验证原生 Panorama LocalStorage、长文本复制粘贴、资源编译和游戏内应用。安装后应确认中英文资源均显示版本 96，再验证手动导入与新局清空行为。
