# 单机闯关与七场天梯对战

本分支进图后先显示模式选择。单机闯关保留原有五颗心、三十关与永久排行榜；天梯对战使用独立积分，初始为 1500。入口需要等服务器确认房主后才能操作，重连会恢复当前模式。

## 天梯流程

选择五名不同英雄，全部升到 30 级，共用 99999 金币。英雄库来自项目完整的 127 英雄目录。准备阶段可学习技能与天赋、配置条件规则、购买装备和移动站位。

第一次正式开始时保存准备配置并锁定英雄与购买功能。后台一次确定七个不同对手，优先从评分相近玩家的已保存阵容中挑选，不足部分用七套不同系统阵容补足。一次系列赛使用同一份对手快照。

胜利后等待三秒自动挑战下一队；失败后恢复配置，进入调整阶段，可修改条件、站位和转移已有装备，不能补买装备、招募或替换英雄。每场开始重新创建双方英雄，恢复准备配置中的物品、充能、技能、天赋、神杖／魔晶／已消耗银月之晶、满血满蓝和冷却。敌队的站位旋转到另一侧，队友与指定敌人的条件引用也按所属队伍解析，双方同名英雄互不串用。

七场完成后自动结算并保存最后一次准备配置，供后续玩家匹配。战斗中的位移、消耗或永久战斗成长不会覆盖这份配置。退出未完成系列不结算积分；网络失败保留操作快照，重试不会重复计分。切换模式会使旧回调失效。

积分按系列开始时的本人积分与每位对手的固定积分计算：

```text
E = 1 / (1 + 10 ^ ((对手积分 - 本人起始积分) / 400))
胜场变化 = max(1, round(32 × (1 - E)) + 存活英雄数 - 3)
负场变化 = -round(32 × E)
最终积分 = max(0, 起始积分 + 七场变化之和 + 完美奖励)
```

七胜且七场累计阵亡为零，额外获得 14 分。重生、复活前的死亡也计入阵亡，幻象与召唤物不计。守方玩家的积分不会因异步挑战而变化。

## 随机测试和文件导出

准备阶段及战败调整阶段可选择较弱、相近、较强的随机敌队进行测试。每次从完整英雄库随机抽五名不同英雄，并按强度设置装备。测试不占七场次数、不上传比赛结果、不改变积分；结束后恢复测试前的己方配置和金币。

“导出配置”上传当前准备配置，生成七天有效的 JSON 下载链接，再由“下载文件”打开浏览器下载。终局导出的是最后准备配置。文件包含五名英雄、等级、技能／天赋等级与剩余技能点、物品槽位与充能、升级效果、条件规则、坐标朝向和共享仓库。该链接可供持有者下载，不含提交密钥。当前功能只提供导出。

## 接口与运行边界

后端沿用公开、免登录的本地主机上报方案。SteamID 和比赛结果由游戏服提供；服务端验证格式并计算积分，但不证明战斗过程真实。游戏服会拒绝跨玩家操作和过期界面请求。

竞技接口位于 `/api/v1/arena/`：玩家资料、创建七场系列、提交七场结果、放弃系列、创建导出与下载文件。D1 的 `arena_players`、`arena_series`、`arena_exports` 与闯关排行榜分开存储。后端代码保持本地，不提交到 Git。

本地回归覆盖模式入口、阵容捕获与还原、队伍相对条件、服务端购买与阶段限制、七场状态机、测试战隔离、最终配置、网络重试与旧回调、UI 与导出。后台 SQLite 测试覆盖原子计分、冻结对手、顺序、并发与幂等；真实远程接口验证匹配、结算、配置保存、JSON 附件和放弃，并清理测试记录。实际 Dota 资源编译通过。

这些验证不等于真实 Dota 战斗验收。还需要在本分支安装／发布版本中进行七场完整流程、原生物品合成与复杂英雄能力布局的实机验收。上传创意工坊仍使用原条目 `3799645167`，游戏版本更新后从新大厅进入。
