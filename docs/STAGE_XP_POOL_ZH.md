# 关卡总经验与全拥有英雄均分

原基准来自 `DESIGN.md` §2.4 的五人玩家测试档案及 §2.6 的「第 30 关开战前五名主力达到 30 级」。旧前 29 关每名上阵英雄经验合计 33720，30 级累计门槛 33700。因此每关基础总池 = 原每名主力经验 ×5；前 29 关共 168600，第 30 关为 0。五人标准难度的逐关成长不变，无需重做该五人基准的敌人等级/装备校准。

| 关卡 | 基础总经验 |
| --- | --- |
| 1–5 | 600 / 800 / 1000 / 1250 / 1600 |
| 6–10 | 1800 / 2100 / 2400 / 2700 / 3250 |
| 11–15 | 3500 / 3800 / 4100 / 4500 / 5250 |
| 16–20 | 5500 / 5900 / 6300 / 6750 / 7750 |
| 21–25 | 8000 / 8500 / 9000 / 9500 / 11000 |
| 26–30 | 11500 / 12000 / 13000 / 15250 / 0 |

运行时关卡配置 `scripts/data/levels.kv` 采用 `reward.xp_pool`；`data/progression_data.lua` 保留原每人曲线作为换算依据，`STAGE_XP` 表示总池。`levels_v07.json` 是旧版本维护资料，不是当前经验奖励来源，本次不改其历史奖励数值。配置导出列也改为「关卡总经验」。

胜利结算先按既有难度倍率对总池取整一次，再均分。时间/星级不增加经验。分母是结算时 `ownedHeroes` 中存在 `heroData` 的唯一英雄名称；重复名称只计一次，缺少成长记录的旧条目跳过。上阵、替补、死亡、满级和暂时没有实体的拥有英雄都计入。无须参战；敌人、召唤物、分身或指挥官不会因出现在战场或阵容名单中获经验。空拥有名单安全地不发经验。满级英雄仍占一份，但自身超额舍弃，不重新分给其他英雄。

份额保留为小数写入 `heroData.current_xp`，例如总池 600、7 人时每人 600/7；不向下取整、不偏袒招募顺序、不在下一关转移余数给新招募英雄。后续经验卷轴也保留原有小数，仅给目标英雄增加固定经验。升级阈值使用 1e-9 浮点容差，防止重复分数累积后卡在整数门槛以下。满级仍清空经验。

`EndBattle` 现有 phase 抢占保障一次结算；败北/平局/超时不发关卡经验，载荷中的经验字段为零。胜利载荷发送 `xp_pool`（倍率后总池）、`xp_per_owned_hero`（每人名义份额）、`xp_recipient_count`（分母）；兼容字段 `xp_per_active_hero` 和 `xp_per_bench_hero` 都是同一份额。满级浪费的份额仍属于名义奖励池。

前端结算直接读取服务端总池与人数，每人份额最多显示两位小数；不按当前本地阵容重算总经验，避免阵容同步延迟改变显示结果。展示精度不会写回成长状态。

验证：使用 Python Lupa 执行 `stage-xp-pool`、`campaign-difficulty`、`shop-transition`、`shop-state`、`battle-reincarnation-lifecycle`、`campaign-loot`、`respawn-policy` 共 7 组 Lua 回归。覆盖 30 关实际 KV 与曲线一致、五人自然满级、所有权去重、替补与死亡策略、小数守恒、分数升级、满级份额、空名单、倍率一次应用、失败零奖励和重复结算。`opening-balance.test.py` 的 3 项配置测试通过。此为离线验证，未做 Dota 实机验收。
