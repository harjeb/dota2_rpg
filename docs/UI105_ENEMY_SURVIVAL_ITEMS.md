# UI105 — 敌方物品条件与主力生存装备

## 物品规则

敌方原先根据当时的主装备栏生成规则，原生执行器也会验证物品是否可用，但规则本身没有显式持有条件。现在每条生成的物品规则增加已注册的 `enemy_has_equipped_item` 条件：执行时必须在0—5主装备槽中找到同名有效实体，背包、仓库、移除后的实体均不能满足条件。原来的血量、魔量、距离、敌方数量等条件保留并按全部满足执行。

现有条件注册表没有通用的物品持有或正向可用条件，因此持有条件作为敌方专用条件注册；冷却、魔耗、禁用及原生施法限制继续由物品执行器验证，不添加未注册的条件名称。

奶酪新增高优先级自用规则：持有生效中的奶酪、充能大于0、生命值比例不高于30%，且原生执行器允许使用时，执行原生无目标施放。该规则排在控制物品、技能及普攻之前；生命与魔法恢复、充能消耗由引擎完成。

肉山盾为原生被动物品，不生成主动施放规则。现有复活策略根据 `IsReincarnating` 放行原生复活，复活等待期间不判团灭，盾消耗后再次死亡没有额外复活许可。保留原生5秒复活、300秒过期机制。

## 验证

- `enemy-item-rules.test.lua`：实际条件求值、奶酪血量边界、规则优先级、充能、被动/隐藏/禁用物品、冷却、原生无目标命令、背包/仓库与移除实体排除。
- `enemy-survival-equipment.test.py`：8名指定英雄与物品、6格生效栏、BKB保留、永久神杖替代前提、其他英雄不变、JSON/KV同步和生成幂等。
- `respawn-policy.test.lua`：增加双方肉山盾复活等待不判团灭、消耗后再次死亡不复活的回归。
- 原生安装包数据确认肉山盾为被动且禁止放入背包，奶酪为立即/无目标、初始1充能、40秒冷却、恢复2500生命/1500魔法。

全套离线检查156组，151通过。5项失败与UI104既存失败相同：Panorama保存测试的同步Schedule递归、预测UI过时断言、原生掉落目录SHA漂移、技能帮助生成数据漂移和原生物品价格漂移；由 `dota2_rpg-flxd` 跟踪。结果见 `tests/results/reliability-regression.json`。装备导出测试同步为531条装备记录，并补充两件新物品的中文名称。未启动或操控游戏；原生引擎实战尚未验证。
