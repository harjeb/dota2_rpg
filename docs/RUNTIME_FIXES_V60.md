# UI60：处理自动换选导致的原生商店关闭

日期：2026-09-12

用户明确反馈 UI59 仍然失败：开商店 → 自动选中小精灵 → 商店立即关闭 → 自动还原英雄。撤销 UI58 的按钮接管没有消除这个序列。UI59 的旧测试把 `SelectUnit` 模拟成只换头像，漏掉了用户观察到的关店副作用，不能作为这条路径的通过证据。

## 修改

- 自动切小精灵前先保存交付目标、原英雄和一次换选过渡标记。原生关闭事件即便同步发生，也不会在这个过渡内触发英雄还原。
- 0.2 秒后检查过渡：头像仍是原英雄时等待异步换选，最多检查五次（一秒），不会把首次检查时尚未生效的换选误认成人工取消。若仍是准备阶段、同一个小精灵已被选中，而且原生 `ShopOpen` 状态明确为关闭，则补一次原生打开请求。已打开、状态不可用、手动改选其他单位、阶段切换或新局均不补开。
- 保留原生 ShopButton 的回调；没有按钮接管。安装版本的 `dota_hud_quick_buy.xml:79` 使用 `DOTAHUDToggleShop()`，`client.dll` 也含此事件。只读字符串检查未找到 `DOTAShopShowShop` 或 `SetShopOpen`，因此不依赖这些未经证实的接口。补开函数在派发零参数 `DOTAHUDToggleShop` 前再次确认状态为关闭。
- 每次自动换选最多补开一次，不持续重试。失败后仍走已有关闭后 0.15 秒还原流程；稳定打开之后的正常关闭不会补开。开店期间改选另一英雄会建立新的过渡和交付目标。
- 增加 `shop selection begin`、`shop selection settled open=...`、`shop selection reopen requested/failed`、取消换选日志，便于下一次实机定位。Lua 的原生购买价格、订单处理、物品转交逻辑未改。

## 验证

`tests/hud-sidebar.test.js` 新增换选导致关店的模拟，覆盖状态类更新前后通知、不发通知、下一帧选中才生效，以及超过首次检查才完成或被引擎拒绝的选中、购买状态更新、随后正常关闭、开店后另选英雄、手动换选、阶段/新局取消、已经自行重开、原生事件抛错或无效果。

将 UI59 的实际 HUD 脚本替换进当前测试后，断言 `selection-induced close must not bounce back to hero before settlement` 失败；UI60 脚本通过。完整 `scripts/test-all.py` 离线测试 87/87 通过。

部署和编译记录见 `tests/results/ui60-shop-close-deploy.json`、`tests/results/ui60-shop-close-workshop.json`。本机 developer addon 和两份本机 Workshop VPK 更新为界面版本 60；原生 Panorama 编译与独立 VPK 校验结果以这些记录为准。

## 实机边界

没有本轮游戏操作或新的引擎事件跟踪；现有 `console.log` 没有本问题的 `[Dota2Rpg]` 记录。0.2 秒是对用户描述的立即关闭设置的过渡检查间隔，异步选中最多等一秒；两者都不是从引擎日志测出的上限。如果玩家恰在自动换选后的首次检查前主动关闭，也会被归入过渡而补开一次；结束过渡后才发生的引擎关闭则不会被恢复，一秒之后才生效的选中也超出了等待边界。故不能宣称原先双击关闭或本轮开店问题已经实机通过。

下一次重载界面版本 60，检查选英雄开店后是否停留在小精灵并保持商店打开、购买是否继续交付原英雄、之后一次关闭是否还原。运行验收由 `dota2_rpg-6vl4` 跟踪；本次实现由 `dota2_rpg-7nf8` 跟踪。未启动/关闭/操控 Dota，未截图、远程上传工坊或修改 Steam 元数据。
