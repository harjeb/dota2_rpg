# UI49 — Witch Doctor Gris-Gris

The preparation roster rebuild used to retain the old Gris-Gris entity while a newly created Witch Doctor received another innate grant. Panel selling called IsSellable, which correctly rejects the native unsellable item. Inventory persistence saved item charges but omitted the hero's native Gris-Gris counter, and the equipment panel exposed no bank balance.

Installed native VPK evidence: `scripts/npc/items.txt` defines `item_grisgris` with cost 0, ItemSellable 0, ItemCanBeConsumed 1, no dropping/backpack, neutral-slot permission, `gold_tick_interval=3`, and `death_gold_lost_reduction_pct=100`. Witch Doctor's innate and localization specify one-time consumption, 1 gold per 3 seconds, and saved actual death losses. Localization identifies `modifier_item_grisgris_counter`. Native implementation is compiled; KV alone does not establish its timer's internal conditions.

`issue_fixes/gris_gris.lua` keeps issued/consumed state, canonical item, bank, and timer remainder in the owned Witch Doctor's heroData. It removes fresh and late duplicate grants without redeeming them. Before ordinary inventory restoration it discards duplicate records and generated items; afterward it restores the native counter when available, including delayed counter creation. A new run's reset heroData starts a new innate entitlement.

The bank uses the greater of cumulative game-time earnings and the native counter, so native and fallback ticks do not add together. It runs during custom preparation, battle and result phases; game pause freezes GameRules time. Rebuilds preserve incomplete 3-second ticks. Actual owner death losses observed in PlayerResource:GetGoldLostToDeath are added as separate principal; other roster deaths do not count. Reliable gold does not incur a death loss, so it contributes zero. Native death event/stat ordering still needs engine acceptance.

The equipment panel shows `护符：已存 N 金` and offers `出售兑现`. This credits all saved gold and permanently removes the item for that run. The panel and native Consume/Sell orders share one server path, including neutral slot 16. That path checks player, holder, exact entity, setup phase and pending purchases, removes the exact item with RemoveItem, verifies destruction, records consumption, and credits the bank once. It deliberately does not combine native ConsumeItem payout with a scripted refund, avoiding delayed native credit double-payment. Ordinary equipment continues using native SellItem. Gris-Gris cannot be unequipped/dropped/transferred by these controls.
