# UI37：中文状态选择、战后装备冷却与等级配装

2026-09-11。运行时标记 `rpg-runtime-v37-20260911`，界面版本 37。

## 状态选择

原菜单直接显示 `CHANNELING` 等生命周期枚举和 `modifier_*` 内部名称。现在九个阶段均有中英文本地化，中文例子包括“尚未施放”“施法前摇中”“已施放”“持续施法中”“施法被打断”。悬停说明区分指令提交、游戏确认出手、持续施法正常结束及结果不明，保留原有条件语义。

具体状态优先读取原生 `DOTA_Tooltip_modifier_*` 名称。服务端从已观察 modifier 的 `GetAbility()` 或技能声明的固有状态取得真实来源，发送字符串元数据；菜单据此显示技能或装备图标。缺少原生状态译名时使用来源技能名，无法识别来源时显示“未命名状态”，不会通过拼接技能名猜测状态标识。重名条目加序号，原始代码可在悬停提示及高级输入中查看。已有规则、手动代码、保存及重新打开仍使用原始标识；未知状态仍须原有高级确认，显示名称不会扩大允许条件集合。

元数据保持原有目录上限（最多 256 个观察记录，每份列表至多 32 个观察状态及当前技能固有状态），不保存可能失效的实体引用，战斗执行检查不加载显示数据。旧服务端只提供名称集合时仍可使用原生本地化名称，图标须重新加载新版服务端后取得。

## 战斗后立即刷新装备冷却

普通 `EndBattle` 原来未刷新装备冷却；重建英雄保留了真实装备实体，因此也保留了剩余冷却。技能测试此前只在延迟重置后刷新。准备状态下无需再依赖原生冷却自行流逝。

新增 `battle/item_cooldowns.lua`，普通结算和技能测试停止时，在认领 `result` 状态后立即调用；准备阶段恢复阵容装备后再清除搬运后残留冷却。胜利、失败、平局、超时及终局都经过结算入口。处理场上双方、死亡持有者、待命英雄、仓库的 0–16 号原生装备槽位，同一实体只处理一次。

仅调用装备的 `EndCooldown()`，不重建物品，不补充充能，不恢复已消耗物品或重置其他物品状态。`fight` 和 `countdown` 中拒绝刷新。

## 敌方英雄装备随实际等级成长

旧生成器按关卡编号选六档出装，并强制保留原装备槽位数；英雄实际等级已与这些档位脱节。新生成器从运行配置 `levels.kv` 读取实际等级，使用已有 64 个英雄的出装定位，更新当前 93 条英雄配置。当前敌方英雄实际为 8–30 级，低等级曲线也可用于后续调级。

| 英雄等级 | 配装阶段 | 当前原生物品价格下的装备总值范围 |
|---|---|---:|
| 1–3 | 基础属性／续航小件 | 460–505 金 |
| 4–6 | 基础鞋与小件 | 960–1,005 金 |
| 7–9 | 升级鞋与小件 | 2,085–2,465 金 |

这是人工配置的 RPG 平衡曲线，**不是网站对战统计或等级对应平均净资产**。以上范围在 2026-09-11 从当前安装的 Dota `pak01_dir.vpk` 中读取 `scripts/npc/items.txt` 的 `ItemCost`，遍历全部 64×30 种组合计算；不包含身上现金、消耗品、魔晶等额外价值。所有使用物品均存在于该原生物品表，每个英雄装备总值随等级不下降。核对时发现旧 `item_halberd` 不在当前原生表，已统一改为 `item_heavens_halberd`，并更正导出表此前的“兼容旧 ID”说明。

实际配置示例：

- 第 5 关 8 级斧王：相位鞋、护腕、魔杖。
- 第 10 关 14 级人马：相位鞋、跳刀、刃甲、魔杖。

生成器避免重复鞋、升级装备与其低级成品同时占格。运行时配置比较确认仅英雄装备改变，等级、阵容、经验、金币、Boss 数值和 AI 字段保持原配置。维护 JSON 同步实际英雄等级，防止再次按旧 30 级配置生成；阵容生成工具也调用新配装入口。

`exports/level_configuration_current/` 的 Excel 与 CSV 已重新导出，支持六个装备栏，包含 448 条装备明细。之后修改等级，依次运行：

```bash
python scripts/author-enemy-equipment.py
python scripts/export-level-configuration.py
```
