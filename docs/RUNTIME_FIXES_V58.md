# UI58：购买后一次点击关闭原生商店

用户实机确认 UI57 已能在打开商店时自动选中小精灵，购买物品也会立即交付给此前选中的英雄；剩余问题是买完后需要点击两次才能关闭商店。

## 修改

安装版本的 `dota_hud_quick_buy.xml` 中，`ShopCourierControls → ShopButton` 原来执行 `DOTAHUDToggleShop()`；原生商店根面板的取消事件使用 `DOTAShopHideShop()`。UI58 在准备阶段读取实际的 `DOTAHUDShop.ShopOpen` 状态：已经打开时，商店按钮明确派发一次 `DOTAShopHideShop`；已关闭、状态未知或处于其它阶段时，继续派发原来的 `DOTAHUDToggleShop`。仅替换 `onactivate`，保留其它右键/提示事件、金币标签及样式，HUD 重建后重新绑定。

UI57 一收到关闭信号就立即 `SelectUnit` 还原英雄。UI58 等待 0.15 秒，超过原生 CSS 的 0.1 秒关闭动画，再检查实际商店状态和当前头像。重新开店、进入战斗或新局都会使旧的还原失效；期间手动改选的单位优先。原生 opened/closed 事件也先读取实际根面板状态，避免过早或延迟通知覆盖可见状态。

这两个环节是根据源码采取的修复措施。用户报告证实双击现象，但没有逐帧引擎证据证明它唯一由 toggle 分支或选中还原时序引起。Lua 购买价格、物品交付及交付目标同步逻辑未修改。

## 验证

- 完整离线套件 87/87 通过。新增 HUD 行为场景验证：一次关闭点击只派发一次 hide；模拟关闭动画期间选择变化会重新打开商店，确认延迟还原避免该竞争；关闭过程中改选、重开、阶段切换、新局、迟到事件及重建按钮均有覆盖。
- 原有商店状态识别、购买目标同步和上下金币显示回归继续通过。
- 原生 Panorama 编译及本机开发插件、两份本机 Workshop VPK 的部署结果记录在 `tests/results/ui58-shop-close-deploy.json` 和 `tests/results/ui58-shop-close-workshop.json`。部署备份保留在记录所列临时目录。
- 模拟测试不代表实机验收。未启动/停止 Dota、执行游戏操作、截图或上传远程 Workshop。需要用户重新载入“界面版本 58”后确认实际一次点击关闭及英雄还原。
