# 阵营卡牌模式：无尽模式的卡牌机制设计 v0.1

> 文档状态：**玩法设计草案，等待确认**。本文取代 [五类英雄与战术卡牌模式](TACTICAL_CARD_MODE_DESIGN.md) 中的分类与稀有度部分：卡牌分类由"坚守 / 猛攻 / 秘法 / 诡术 / 生息"改为**五个阵营**，稀有度三档改为**同名合成升级**。旧稿保留为历史，不删除。
>
> 本次仅同步设计，不修改代码、不安装、不递增 UI 版本号。
>
> 关联：
> - [英雄阵营归属表](HERO_FACTION_MAPPING.md)：五阵营的定义、122 名英雄归属、首轮开放子集
> - [阵营组合 buff 设计表](FACTION_COMBO_BUFFS.md)：单/双/三阵营档位、命名键、叠加待确认项
> - [独立无尽模式设计](ENDLESS_MODE_DESIGN.md)：独立 addon、无存档、无排行榜、五命与波次规则
>
> 该模式沿用无尽模式的边界（独立 addon、无存档、无排行榜、无后端），卡牌只是无尽模式内新增的一层构筑。

## 1. 本次改动的四个要点

| 项目 | 旧稿（战术卡牌模式） | 本文 |
| --- | --- | --- |
| 卡牌分类 | 坚守 / 猛攻 / 秘法 / 诡术 / 生息（按战斗风格） | **五阵营**：元素 / 文明 / 神域 / 深渊 / 荒野（按英雄分类） |
| 获取方式 | 金币购买，商店 4 格报价 | **每波免费抽卡**，可选金币额外抽 |
| 成长方式 | 三档稀有度（普通/稀有/史诗），价格分层 | **同名卡 3 张合成升 1 阶**，最高 Lv3；取消稀有度与卡牌价格 |
| 上牌方式 | 每场战术点预算，战败返还 + 战术点补偿 | **每名上阵英雄固定 2 个卡槽**（1 专属 + 1 通用），无战术点 |

被移除的机制：战术点、战败战术点补偿、卡牌金币价格、稀有度抽取权重。这些是旧稿的核心节奏设计，移除后需要新的节奏来源（见 §12-1），**这是本文最需要确认的一项**。

## 2. 核心循环

```text
本波准备阶段
  → 免费抽卡（3 张）
  → 把卡装到上阵英雄的 2 个卡槽（1 张阵营专属 + 1 张通用）
  → 同名卡合成升阶（3 张 → 1 张高一阶）
  → 查看敌情，开战校验，冻结卡牌快照
  → 自动战斗
  → 胜利：卡全部保留，进入下一波
  → 失败：扣 1 命，卡与装备全部保留，本波重新配卡
```

卡牌是**局内资产，跨波保留**，不因战斗消耗。这与旧稿"出牌即消耗、战败返还"完全相反——因为合成升级需要玩家长期积累同名卡，卡如果每场消耗掉，合成就无从发生。

## 3. 卡牌分类

系统里只有两种卡：

| 类型 | 分类方式 | 装备限制 | 数量（首轮） |
| --- | --- | --- | ---: |
| **专属卡** | 按五阵营分 5 大类，这就是"5 大类卡牌" | **只有该阵营的上阵英雄能装备** | 每阵营 5 张 = 25 张 |
| **通用卡** | 不分阵营 | 任何上阵英雄都能装备 | 8 张 |

规则：

- **所有卡都是纯增益**，没有负面效果、没有代价型卡、没有诅咒卡。
- 卡牌效果**只在本场战斗生效**，战斗结束清除。不直接增加永久属性、金币、经验或生命次数。
- 专属卡的阵营 = 该卡所属阵营。元素阵营的英雄只能装备元素专属卡，不能装备文明专属卡。
- 通用卡没有阵营，因此不参与阵营组合计算，也不影响单阵营等级。
- 卡牌的阵营与八类羁绊标签是两套独立分类，互不取代。

## 4. 卡槽与装备

| 项目 | 首轮建议 |
| --- | --- |
| 每名上阵英雄卡槽 | **2 个**：1 个专属槽 + 1 个通用槽 |
| 阵容 8 人时最多装备 | 8 张专属 + 8 张通用 = 16 张 |
| 同名卡 | 同一名英雄的两个槽不可能同名（槽位分类不同）；不同英雄可以装同名卡 |
| 同名卡全队上限 | 同一张卡全队最多装备 **3 份**，超出的实例可以持有但不能装备（防止极端堆叠） |
| 实例 | 每个卡牌实例独立，同一实例只能占用一个槽 |
| 换人 | 英雄被换下或卖出时，其卡退回卡库，可重新分配；不吞卡、不自动转移给替补 |
| 换阵预览 | 准备阶段换阵实时预览卡槽与效果；开战校验后冻结为本场快照 |
| 战斗内 | 不能换卡、不能用卡、不能合成。战斗中英雄死亡**不解除**已生效的卡效果，复活**不重置**一次性卡（如"每场一次"的触发） |
| 召唤物 | 卡牌效果默认只作用于装备者本人，除非卡面明确写了"全队"或"范围" |

## 5. 抽卡

| 项目 | 首轮建议 |
| --- | --- |
| 免费抽卡 | 每波准备阶段免费抽 **3 张**，进入下一波重置 |
| 卡池来源 | **本波上阵英雄所属阵营**的专属卡 ∪ 全部通用卡 |
| 为什么按上阵阵营 | 保证抽到的专属卡一定有英雄能装，不产生死卡；代价是换阵会改变卡池 |
| 额外抽卡 | 100 金抽 1 张，每波最多 2 次 |
| 卡库上限 | 12 张；超出时必须先合成或主动弃置才能继续抽 |
| 弃置 | 准备阶段可弃置，无返还，不触发任何效果 |
| 抽取确定性 | 由 `run_seed + wave + 卡库操作序列` 决定；失败重试不重抽卡、不重roll卡池 |
| 已抽卡的保留 | 抽到即进卡库，跨波保留，不因换阵失效（只是临时装不上） |

卡池会随阵容变化，而卡库存量不变，所以玩家可以先囤某阵营的卡，再专门组那个阵营的阵容——这是这套系统里"抽卡 → 组阵"的正向循环。

## 6. 合成升级

| 项目 | 首轮建议 |
| --- | --- |
| 合成公式 | **同名同阶 3 张 → 1 张高一阶** |
| 阶位 | Lv1 → Lv2 → Lv3，Lv3 封顶 |
| 消耗 | 合成不花金币 |
| 时机 | 只在准备阶段，即时生效，不可撤销 |
| 装备中的卡 | 不能参与合成，必须先卸下（避免合成后卡槽状态歧义） |
| 命名键 | `card_<卡id>_<阶>`，例如 `card_element_resonance_2` |
| 跨波 | 合成结果跨波保留，是局内唯一的纵向成长 |

升级幅度按 §7 的数值表逐阶递增，**Lv3 相对 Lv1 大约 1.5～1.8 倍**，不出现阶跃式的倍率爆炸。

## 8. 叠加与上限

卡牌效果与阵营羁绊、职责层羁绊进入**同一叠加组**，共用全局上限（`FACTION_COMBO_BUFFS.md` §7-1 与 §7-5 尚未定案，本文沿用其约束框架）。卡牌侧首轮上限：

| 效果组 | 规则 |
| --- | --- |
| 卡牌攻击伤害 | 加法，最多 +30% |
| 卡牌攻速 | 加法，最多 +50 |
| 卡牌移速 | 加法，最多 +18% |
| 卡牌技能增强 | 加法，最多 +25% |
| 卡牌受到伤害降低 | 同一伤害事件合并，最多 20% |
| 卡牌护甲 | 加法，最多 +12；不影响英雄原生护甲与减甲 |
| 卡牌护盾 | 每目标所有卡牌护盾合计最多为开战最大生命的 30% |
| 卡牌治疗增幅 | 加法，最多 +35% |

上限只约束卡牌体系，不改写 Dota 原生装备与技能。反伤与卡牌追加伤害统一标记为 `card_secondary`，不触发另一张卡的连锁，也不触发攻击特效。

## 9. 与技能条件、敌情和阵容的关系

- 卡牌不覆盖玩家规则，不自动更换技能顺序或强迫集火。
- 卡牌不产生新的目标筛选条件；如需"对卡牌标记目标"这类行为，走条件系统的独立筛选（旧稿 §8 的做法），本版不做。
- 卡片效果不区分敌人是英雄还是野怪，除非卡面写明。首轮所有卡都写成通用表述，避免"指定敌方英雄"在野怪波变成死卡。
- 换人、卖出、替换目标后，受影响卡退回卡库并提示重新分配。
- 战斗中死亡不转移效果；复活后持续效果只保留原定到期时间，不重新计时。

## 10. 界面草案

准备阶段突出三件事：敌人、卡槽、卡库。

- 顶部显示 `生命 4 / 5`、`波次 7`、`金币 1200`、`本波免费抽卡 3 次已用`。
- 每名上阵英雄卡片下方显示 2 个卡槽：左边专属槽（空槽显示"需要<阵营>专属卡"）、右边通用槽。
- 卡库显示名称、阵营图标、阶数（1/2/3 个方块）、一句效果、当前装备者。
- 合成入口：卡库里同名同阶达到 3 张时高亮"可合成"，点击预览升级后的数值。
- 开战时提示：`已装备 14 / 16 张卡，同名卡上限检查通过`。
- 战斗内只显示本场生效的卡与剩余触发次数，不可操作卡库。

文字、图标、阶数同时表达，颜色只作辅助。中英文同步。

## 11. 数据与实现

推荐数据分离，均在无尽版独立数据域内：

```text
scripts/data/hero_factions.json    英雄 → 阵营（见 HERO_FACTION_MAPPING.md §6）
scripts/data/cards.json            卡牌定义：id、类型(专属/通用)、阵营、各阶效果
scripts/data/card_combos.json      合成规则（同名同阶 3 → 1）
scripts/data/endless/*.kv          生成的运行时数据
```

运行时分别维护：卡库实例（含阶数）、每个英雄的槽位占用、本场快照。**客户端不能提交卡牌数值、阶数、槽位判定或合成结果**；所有请求只表达操作意图，由服务器校验 `run_id`、准备阶段、实例归属与同名上限。

开战事务沿用无尽模式的全有或全无流程：校验阵容与卡槽 → 生成卡牌快照 → 应用 modifier → 创建 `battle_id` → 进入战斗。应用失败则移除本次已加效果并停留准备阶段，不扣命。

## 12. 待确认项（按影响排序）

1. **节奏来源**。移除战术点、卡牌价格和战败补偿后，玩家每波只有 3 张免费卡，前期强度增长会明显变慢。三种处理：
   - a) 保留免费抽卡，接受更慢的节奏（最贴近"每轮抽卡"的字面设计）；
   - b) 免费抽卡 + 每波一次商店直购指定卡（花金币买确定性的卡，缓解随机）；
   - c) 恢复旧稿的战术点，只让战术点决定每场能带几张卡（与"固定 2 槽"冲突，需二选一）。
2. **"专属"的定义**。本文按**阵营专属**理解（元素英雄只能装元素卡，因此天然分 5 大类）。若你的本意是**英雄专属**（每名英雄有自己独有的卡，只有他能装），需要改成：先给首轮 30 名英雄各做专属卡，通用卡维持不变。这个选择直接决定卡池规模（25 张 vs 30 张起）和是否需要给 122 名英雄全部配卡。
3. **卡牌是否消耗**。本文假设不消耗（跨波保留、靠合成成长）。若改成"胜利后装备的卡消耗"，则合成本身会与消耗互相抵消，需要重新设计合成资源。
4. **合成比例**。本文用 3:1。若改成 2:1，Lv3 的达成速度会快很多，需要同步下调 Lv3 数值。
5. **卡池来源**。本文用"本波上阵英雄所属阵营"。备选是"本局开局选择的阵营"（旧稿做法），更稳定但会产生装不上的死卡。
6. **同名卡全队上限 3 份**、**卡库上限 12 张**、**每波额外抽 2 次 100 金**这三个数字都是占位值，需要试玩调平衡。
7. **与阵营羁绊的叠加**。卡牌与 `FACTION_COMBO_BUFFS.md` 的单/双/三阵营 buff 是否进同一叠加组、是否共享受益上限，需要和该文档 §7-5 一起定。
8. **是否保留旧稿的三档稀有度**。本文用合成阶数替代稀有度。若两者都要（稀有度决定抽卡权重、阶数决定强度），抽取概率表需要重做。

## 13. 必须验证的行为（确认后作为实现验收）

| 场景 | 预期 |
| --- | --- |
| 元素英雄 + 文明专属卡 | 拒绝装备并提示阵营不符 |
| 任意英雄 + 通用卡 | 允许装备 |
| 同名卡装在第 4 名英雄 | 拒绝装备，实例保留在卡库 |
| 同名同阶 3 张合成 | 得到 1 张高一阶，卡库减去 3 张 |
| 装备中的卡参与合成 | 拒绝，提示先卸下 |
| Lv3 卡再次凑满 3 张 | 不消耗，提示已达最高阶 |
| 换下英雄 | 卡退回卡库，可重新分配，不吞卡 |
| 开战校验与快照 | 战斗中改卡无效；死亡/复活不重置一次性触发次数 |
