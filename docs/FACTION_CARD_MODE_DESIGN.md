## 1. 已定参数

| 项目 | 决定 |
| --- | --- |
| 卡牌两大类 | **基础卡**按五阵营分类（每阵营 20 张）；**专属卡**绑定单个英雄（每英雄 2 张） |
| 专属卡分层 | 每英雄 **1 张普通 + 1 张特殊**。普通卡始终在卡池里；**特殊卡只有招募该英雄后才进入卡池** |
| 基础卡类型 | 增益卡 9 / 消耗卡 7 / 场地卡 4（每阵营 20 张的固定配比） |
| 卡槽 | 每名上阵英雄 2 个槽：1 专属槽 + 1 通用槽。**场地卡占用通用槽** |
| 资产规则 | **唯一资产**：每张卡全队只有一份，只能装备在一个槽上 |
| 等级 | **Lv3 封顶**：累计同名 **1 / 2 / 3 张** → Lv1 / Lv2 / Lv3 |
| 抽卡 | 每波报 **5 张纯随机**（单池），**只见卡背**，付费购买 |
| **购买次数** | **每波准备阶段最多购买 3 次，买英雄与买卡合并计数** |
| 熔炼 | 燃料**只限同阵营专属卡**（基础卡不可熔）。**1 份 → 1 点阵营点数；3 点 → 任意 1 张同阵营基础卡**（不能兑换专属卡）。**按份数计算** |
| 超上限加值 | **只适用于基础卡**：基础卡到 Lv3 后再获得同名份数不再升级，转为该卡的**永久加值**（每份 +1）。专属卡**不参与加值**，Lv3 之后多出的份数只能用于熔炼。属性口径与上限为占位值（暂写 +1 智力、上限 99），见 §6.2 |
| **卡牌 COST** | 每张卡的 COST **由本场装载等级决定**，装载等级不得高于拥有等级；曲线按卡强度分档（普通 1/5/10、强力 1/6/15、顶级 1/8/20）；**全部已装备卡的总 COST 不得超过本场上阵英雄的等级之和**（见 §2.1） |
| 卡池 | 所选阵营的 20 张基础卡 + 该阵营英雄的普通专属卡 + 已招募英雄的特殊专属卡 |
| 效果持续 | 只在本场战斗生效，战斗结束清除 |
| 效果设计状态 | 卡表中的效果、目标、触发条件与数值均为 demo；正式设计以全友方受益和自然联动为方向，不把旧 demo 当成已定规则 |

### 1.1 当前确认的构筑框架

- **卡牌效果作用于所有友方，而不是只作用于装备者**。英雄提供卡槽与 COST 预算，已装备卡共同构成全队的战斗机制；两名英雄分别携带基础卡即可形成联动，不需要把两张基础卡装在同一名英雄上。
- **保留每名英雄 1 专属槽 + 1 通用槽**。全队受益不改变专属卡的归属与装备资格。专属卡具体如何把英雄特色转化为全队效果尚未设计，旧 demo 中“只强化该英雄技能”的效果不能直接作为正式实现依据。
- **拥有等级与装载等级分离**。累计份数决定拥有等级，准备阶段可在已解锁等级中选择 Lv1 / Lv2 / Lv3 装载；效果、COST 与本场可用次数都按装载等级计算。
- **现有 100 张基础卡与 60 张专属卡全是 demo**。联动方向已经确定，具体效果、触发方式、数值、上限和 COST 分档仍需设计，不围绕 demo 数值先行做平衡结论。
- 全队受益与计数范围是不同概念：设计默认采用**各友方分别判断自身状态、分别计数与触发**；只有明确写“全队共享”的效果才共同计数。正式卡面须明确次数按目标还是全队计算，不能隐式把一次事件广播成多次触发。
- 联动设计可按**启动、收益、保障**三种角色组织，并把原生英雄技能作为状态来源；不要求每张卡都参与联动，也不额外增加联动规则表。
- **友方单位范围仍须细化**：已确认不是仅装备者受益；召唤物、幻象、支配单位是否属于具体卡的受益对象，须在正式效果中明确，不由“全队”一词隐式推导。

## 2. 卡槽与装备

| 项目 | 规则 |
| --- | --- |
| 专属槽 | 只能装**该英雄自己的专属卡**（普通或特殊皆可） |
| 通用槽 | 装基础卡（增益 / 消耗 / 场地任意一种） |
| 8 人上阵 | 最多 16 张卡同时生效 |
| 唯一资产 | 同一张卡不能同时装在两处，因此每名英雄必须配不同的卡 |
| 卡库上限 | **24 张未装备卡**；已装备的卡不占卡库容量。同名累计份数不额外占位。8 人装满 16 槽时，可另存 24 张未装备卡，合计最多 40 张不同卡 |
| 换人 / 卖出 | 卡退回卡库，可重新分配；不吞卡、不自动转移给替补 |
| 开战 | 准备阶段实时预览；开战校验后冻结为本场快照 |
| 战斗内 | 不能换卡、不能熔炼、不能调整。英雄死亡不解除已生效效果；复活不重置"每场一次"类触发 |
| 默认作用域 | **所有友方受益，不限于装备者本人**；各自状态与共享计数须由正式效果明确，**场地卡作用域已确认是全战场**，旧卡表「自身」目标列不构成限制 |
| 召唤物等单位 | 召唤物、幻象与支配单位的受益资格留待正式效果定义，不沿用旧 demo 的排除规则作为定案 |

### 2.1 COST 预算

| 项目 | 规则 |
| --- | --- |
| COST 来源 | 每张卡的 COST **由装载等级决定**，且曲线按卡强度分档；基础卡与专属卡都算，拥有等级只决定可选装载等级上限 |
| 预算上限 | **= 本场上阵英雄的等级之和**（全队共享，不是每名英雄各自为政）。开局 2 名 1 级英雄 → 上限 2 |
| 校验时点 | 准备阶段实时预览；开战校验时冻结为快照 |
| 与槽位的关系 | 两个限制同时生效：上阵 8 人 = 16 个槽，且**全部已装备卡的总 COST ≤ 上限** |
| 超出处理 | 禁止开战并高亮超标的卡槽，不自动卸卡 |
| 换人影响 | 换下高等级英雄会降低上限，可能使当前配卡失效。此时阻止开战，玩家可降低装载等级或卸卡；不静默改动配装 |
| 升级影响 | 抽到重复卡提升拥有等级，**保留当前装载等级与 COST**，只解锁更高装载档位；玩家主动调整后才更新效果与预算，不会让既有配装失效 |
| 装载选择 | 准备阶段可选 `1 ≤ 装载等级 ≤ 拥有等级 ≤ 3`；拥有 Lv3 可按 Lv1 / Lv2 / Lv3 使用，不销毁份数、不需要熔炼 |
| 装载快照 | 效果、COST 和本场可用次数均按装载等级结算；开战后冻结，战斗内不可调整 |

**COST 曲线分档**

| 卡强度档 | Lv1 | Lv2 | Lv3 | 适用 |
| --- | ---: | ---: | ---: | --- |
| 普通 | 1 | 5 | 10 | 多数增益卡与消耗卡 |
| 强力 | 1 | 6 | 15 | 场地卡、专属卡、高价值效果 |
| 顶级 | 1 | 8 | 20 | 极少数，如"无敌 N 秒"这类顶级效果 |

**绝大多数卡的 Lv3 在 15 以内，20 只留给极少数顶级效果。**

**预算与可装载量**（8 人上阵）

| 阶段 | 预算 | 全装 Lv3 普通卡（10） | 全装 Lv3 强力卡（15） | 全装 Lv3 顶级卡（20） |
| --- | ---: | --- | --- | --- |
| 开局 | 2 | — | — | — |
| 第 10 波（约 8 级） | 64 | 只能带 6 张 | 4 张 | 3 张 |
| 第 30 波（约 24 级） | 192 | **16 张全满（160）** | 只能带 12 张 | 9 张 |
| 8 人满级 | 240 | 全满且富余 | **刚好全满（240）** | 12 张 |

这个梯度就是设计目标：**普通卡第 30 波前后能全满，强力卡要接近满级才刚好装满，顶级卡永远带不满**。

**边际效率**（以"奥术共鸣"这类普通增益卡为例：Lv1 +6% / Lv2 +10% / Lv3 +15%）

| 等级 | COST | 效果 | 每 COST 效果 |
| --- | ---: | --- | ---: |
| Lv1 | 1 | +6% | **6.0** |
| Lv2 | 5 | +10% | 2.0 |
| Lv3 | 10 | +15% | 1.5 |

以上仅展示旧 demo 的计算方式，不代表约 4 倍效率差已经被接受或验证。正式效果尚未设计，全友方受益下还须考虑受益人数与触发频率；不能据此认定升级收益或 COST 平衡合理。

**上限曲线**（按战役经验曲线与 `STAGE_XP_POOL_ZH.md` 的均分规则估算，上阵人数取 8）

| 招募情况 | 第 3 波 | 第 5 波 | 第 10 波 | 第 30 波 |
| --- | ---: | ---: | ---: | ---: |
| 招 8 个、全部上阵 | 24 | 32 | 64 | 192 |
| 招 5 个、全部上阵 | 15 | 30 | 55 | 150 |
| 招 16 个、只上阵 8 个 | 24 | 32 | 48 | 144 |

两条从这个表里读出来的结论：

1. **多招人会让卡牌预算变少**。经验按所有已拥有英雄均分（`docs/STAGE_XP_POOL_ZH.md`），招了不上阵就是纯稀释。于是"多招募 → 专属卡可用、阵容灵活"与"少招募 → 等级高、卡牌预算高"形成天然对冲，不需要额外惩罚。
2. **预算的绝对量不小，但顶价卡仍然装不满**。第 30 波 192 的上限下，16 槽全装顶价卡仍差 128，所以限制靠的是"顶价卡的单价"而不是"预算不够花"。

**记录一个取舍**：上限是**全队共享**（上阵英雄等级之和），不是每名英雄各自限额。区别在于全队共享**允许把预算集中到少数英雄身上**：

| 阶段（8 人上阵） | 全队共享上限 | 若改成每英雄各自限额 |
| --- | ---: | --- |
| 第 12 波（约 10 级） | 80 → 能装 4 张顶价卡 | 每人 10 → 一张 20 COST 卡都装不了 |
| 第 30 波（约 24 级） | 192 → 能装 9 张顶价卡 | 每人 24 → 最多 8 张（每人 1 张） |

后期两者接近，**前期差一倍以上**。当前按全队共享实现；若希望"每个英雄都必须自己练到等级才能用顶价卡"，再改成每英雄各自限额。

**与无尽模式的冲突（必须先解决）**：`ENDLESS_MODE_DESIGN.md` 规定 31 波起奖励档位固定在第 30 波档位，而战役第 30 关的 `xp_pool` 是 **0**（战役预期此时已满级）。照搬会导致无尽版 31 波之后英雄等级不再增长，COST 上限随之冻结，本机制在中后期失效。无尽版必须有自己的波次经验曲线。

## 3. 抽卡与购买次数

| 项目 | 规则 |
| --- | --- |
| 每波报价 | **5 张**，纯随机单池，无免费张 |
| 可见性 | 只见卡背，卡背显示**阵营徽章 + 类型图标**（增益/消耗/场地），不显示卡名、等级与数值 |
| 购买次数 | **每波最多 3 次，英雄购买与卡牌购买共用这个额度**。买了 1 个英雄就只剩 2 次买卡 |
| 未购报价 | 作废，换波重新生成 5 张 |
| 卡池 | 所选阵营的 20 张基础卡 ∪ 该阵营全部英雄的普通专属卡 ∪ 已招募英雄的特殊专属卡 |
| 确定性 | 由 `run_seed + wave + 购买序列` 决定；失败重试不重抽、不重roll |
| 招募当波 | 新招募英雄的特殊专属卡**当波不重roll 报价**，从下一波开始有机会出现（见 §14-4） |

**为什么购买次数是关键旋钮**：它和熔炼的慷慨比例互相咬合。不加限制时"熔炼 3:1"会让一张基础卡约 3 波就满级，过快；加限制后节奏落到下面这个区间。3 次相比 2 次整体快约 1.5 倍，换来的是开局不再干（招满 8 人从 4 波压到 3 波）。

**卡池规模与进化速度**（1 阵营、废卡率按 0 招募时的 56% 计、每波 3 次购买全部用于买卡）

| 指标 | 3 次/波 | （对照）2 次/波 |
| --- | ---: | ---: |
| 招满 8 人阵容 | 3 波 | 4 波 |
| 每波获得卡牌 | 3 张 | 2 张 |
| 每波燃料（废专属卡） | 约 1.7 张 | 约 1.1 张 |
| 每波换得的指定基础卡（3 燃料 = 1 张） | 约 0.56 张 | 约 0.37 张 |
| **一张基础卡满级（累计 3 张）** | **约 5.4 波** | 约 8 波 |
| 配满 16 个槽全 Lv3 | 约 86 波 | 约 130 波 |
| 单卡加值堆到 99（99 × 3 燃料） | 约 177 波 | 约 265 波 |

招募英雄后废卡率会从 56% 下降，实际进度比上表略快。选 3 个阵营会让池子从 46 张涨到约 126 张，但因为有熔炼兜底，稀释的影响被大幅抵消。

## 4. 进化

| 项目 | 规则 |
| --- | --- |
| 形式 | **累积式**：卡是唯一实例，记录"累计获得同名份数"，不产生第二份实例 |
| 阈值 | 累计 **1 / 2 / 3 份** → Lv1 / Lv2 / Lv3；第 4 份及以后不再提升 |
| 展示 | 卡面显示 `2/3` 形式的进度 |
| 时机 | 抽卡与兑换即时结算，不需要手动合成、不花金币 |
| 溢出（基础卡） | Lv3 之后多余的份数不提升等级，转为**超上限加值**（见 §6.2） |
| 溢出（专属卡） | Lv3 之后多余的份数不提升等级，**不转加值**，只能用于熔炼（见 §6） |
| 与槽位 | 进化不改变装备状态与当前装载等级；仅更新拥有等级和可选档位。玩家主动切换装载等级后，才更新效果、次数与 COST 预览 |

**消耗卡的进化轴**：累计份数解锁拥有等级，实际效果和次数按**装载等级**计算。保留装载 Lv1 / Lv2 / Lv3 对应本场 1 / 2 / 3 次的框架；次数按各受益单位还是全队共享须在正式效果中写明（默认各自计数，见 §1.1），具体触发条件与数值仍是 demo。

## 5. 三类基础卡的行为定义

> 下表保留类型与生命周期草案。增益、消耗效果由所有友方受益，不能把携带者视作唯一受益者。普通增益/消耗卡的携带者仅提供槽位，已生效效果不因其死亡撤销；场地卡已确认**覆盖全战场**（无范围、不锚定携带者）、**可以互相叠加**、并且**永不失效**（装备者阵亡、复活、换人都不影响）。

| 类型 | 装备位置 | 触发方式 | 生命周期 | 进化提升 |
| --- | --- | --- | --- | --- |
| 增益卡 | 专属槽或通用槽 | 持续被动，开战即生效 | 本场战斗 | 数值 |
| 消耗卡 | 专属槽或通用槽 | **战前设定触发条件，战斗中自动触发**（复用现有条件系统，不做战斗内手动点击） | 本场用掉即失效，**战后回到卡库**（卡本身不消失） | 数值 + 本场可用次数 |
| 场地卡 | 只能装通用槽 | 开战即生成**覆盖全战场**的场地效果（无范围、不锚定装备者） | 本场战斗；**开战生成后永不失效**（装备者阵亡 / 复活 / 换人都不影响） | 数值 |

场地卡补充：

- **覆盖全战场**（已确认）：没有范围参数，不锚定装备它的英雄、不跟随移动；战场内所有相关目标无论距离都受影响。
- **不同场地卡可以叠加**（已确认）：各自独立结算、效果同时作用于全场，因此在场上永远是一起生效的（不存在站位重叠问题）。唯一资产下同名场地卡不可能出现两份。
- **没有失效条件**（已确认）：装备者阵亡、复活、换人或被驱散都不影响已生成的场地，它持续到本场战斗结束。
- **场地效果没有使用者**（已确认）：场地卡生成的效果**不归属装备它的英雄**——不算作该英雄造成的伤害或治疗，不继承他的属性、专属卡与技能联动。因此**英雄自己的技能（含技能回血）不会被自己装备的场地卡放大**；反过来，像「场地效果按**携卡英雄主属性合计**提高」这类条款只强化**场地层**，不强化英雄自身技能。
  - 增幅算式（已定案，`CARD_SYNERGY_AXES_CANDIDATES.md` §H）：把**出场且装备了场地卡的英雄**的主属性**相加**（全才英雄取三项属性最高值），`增幅 = Σ主属性 × 0.1%`，**500 点 = +50% 封顶**。它仍然只是**单向**关系（英雄属性 → 场地效果），不会把场地收益再算回英雄技能。
  - 结算顺序（写死一次，防自举环）：`① 按不含本卡加成的属性算出 Σ主属性 → ② 得增幅 X% → ③ 把 X% 施加到所有场地效果（含本卡自己的 +20n）`。一遍算完、**不迭代**，因此不存在「加属性 → Σ 变大 → 增幅更大 → 属性更高」的环。
- **"开战前生效"是一类独立时机**（随核心卡「共鸣领域」引入）：属性类效果在**准备阶段**结算——装备即生效、可反复重算，开战时快照冻结，战斗内不再变动。好处是没有战斗内结算、不会与"每 X 秒"类效果抢顺序，也天然消除"全属性抬高主属性 → 增幅更大"的自举环；代价是**形态 / 幻象 / 召唤物不另行施加**（它们出现时本就继承带加成的英雄属性）。该类效果**按卡牌等级解锁**：「共鸣领域」的「全知全能」**只有 Lv3 才给，Lv1 / Lv2 完全不给属性**（Lv1 / Lv2 只给增幅低档 +20% / +35%，Lv3 才是 +50%）。
- 场地卡不是召唤物：不会被驱散、不占单位数、不触发召唤相关联动。

## 6. 熔炼与阵营点数

| 项目 | 规则 |
| --- | --- |
| 换算 | **熔炼 1 份同阵营专属卡 → 1 点该阵营点数；3 点 → 兑换 1 张任意同阵营基础卡** |
| 计量单位 | **按份数**。Lv2 的卡（累计 2 份）可以只熔掉 1 份，退回 Lv1 并得 1 点，不浪费进度 |
| 燃料范围 | **只限专属卡，基础卡不可熔**。用不上的专属卡是唯一燃料来源 |
| 兑换范围 | **只能兑换基础卡，不能兑换专属卡**。专属卡只能靠抽 |
| 点数记账 | 按阵营分别记账（元素点数、文明点数……互不通用），**跨波保留**，不设过期 |
| 时机 | **只在准备阶段**，战斗中和开战校验后都不能动 |
| 装备限制 | **已装备的卡不能熔**，必须先卸下；熔炼需要二次确认 |
| 兑换结果 | 兑换来的基础卡进卡库，**照常计入同名进化进度**（等同抽到一份） |
| 溢出 | **专属卡** Lv3 之后多出的份数保留在卡上，作为可熔炼份数（1 份 = 1 点）；**基础卡**的溢出不走熔炼，改为累计加值（见 §6.2） |

设计意图：卡牌有两条明确的出路，互不抢占。

- **专属卡 → 熔炼 → 阵营点数 → 指定基础卡**：解决"抽到用不上的专属卡"的挫败，同时让基础卡的进化可以被规划。
- **基础卡 → 超上限加值**：解决"满级之后继续抽到同一张"的浪费，给长局一个不封顶但有上限的成长出口。

因为不能兑换专属卡，熔炼不会让抽卡失去意义；专属卡依然只能靠抽，负责"抽运气的惊喜"。

一个需要接受的副作用：熔炼会明显抵消"少选阵营"的必要性。若实测发现玩家普遍选满 5 个阵营，应调整**抽卡单价**或兑换比例，而不是改回分池。

### 6.1 燃料供应测算

1 阵营、0 招募时，池子 46 张（20 基础 + 26 普通专属）里真正用不上的是那 26 张普通专属卡。每波 3 次购买、废卡率 56% → 约 1.7 张燃料/波 → 0.56 张指定基础卡/波 → **一张基础卡满级约 5.4 波**。把燃料收窄成只剩专属卡**没有改变这个节奏**，因为用不上的卡本来就是专属卡，基础卡从来不该被烧。

### 6.2 超上限加值（**只适用于基础卡**）

| 项目 | 规则 |
| --- | --- |
| 适用 | **仅基础卡**。专属卡不参与这条机制，Lv3 之后多出的份数只能熔炼 |
| 触发 | 基础卡已达 Lv3 后，再获得该卡的同名份数（来自抽卡或阵营点数兑换） |
| 效果 | 该卡**加值 +1**，上限 **99**（上限也是占位值）；每点加值提供 **+1 点属性**——**占位口径，预设为智力，实际口径待定** |
| 归属 | 加值记在卡实例上，装备时作为该卡效果的一部分作用于所有友方，卸下即失效；具体收益与低等级装载时的加值处理尚未设计 |
| 时效 | "永久"指**本局内永久**，跨波保留、不因战斗结束清除；不属于 Dota 原生属性成长 |
| 展示 | 卡面在等级方块旁显示 `加值 +12 / 99` |
| 上限行为 | 加值已满 99 后再获得同名份数，不再产生任何收益（此时该卡才真正变成死卡） |

**机制已定，数值未定**：这条加值线的**结构**是确定的（基础卡 Lv3 后每多一份 +1 加值、装备时生效、本局永久、有上限），但"每点加值换什么"只是我按你说的预设写了智力，**实际会改**。设计时按以下方向替换即可：

| 备选口径 | 说明 |
| --- | --- |
| 按卡阵营给对应属性 | 元素/神域 → 智力，文明/深渊 → 力量，荒野 → 敏捷 |
| 通用战力 | 每点 +1 攻击力 +1 护甲，或 +0.5% 最大生命 |
| 单一属性（当前占位） | 每点 +1 智力；对力量/敏捷英雄几乎无用，只对法系生效 |

替换口径时要注意：**不要给百分比或乘算类属性**。加值最多 99 层，百分比会被放大成失控的曲线，也会和羁绊、装备的加成叠加出难以平衡的数值。

同理，**加值上限 99 也是占位值**：按当前经济，堆满一张卡需要 297 张燃料、约 177 波，实战里摸不到，等于软性无限成长。若希望封顶真的有意义，把上限降到 20 左右更合适。

### 7.6 联动设计方向（待落地）

**准则：联动不做成规则表，而是让卡去操作同一个"量"。同一条轴上既有"写"的卡、又有"读"的卡，搭配就自然发生。**

用户给出的原型例子：

- 深渊：「开场消耗 20% 生命，转为自身护盾」——**写**生命
- 荒野：「生命百分比越低，攻击力越高」——**读**生命
- 两张卡由不同英雄携带时，仍共同作用于所有友方；每名受益友方分别以自己的生命与护盾状态参与联动，不要求两卡同槽主。
- 此处数值只是概念 demo，正式效果尚未设计；连续缺血收益与阈值触发须区分，不把“扣 20% 血”直接等同于“低于 50%”。

**关键做法：不是设计组合，而是分配轴。** 把同一条轴上的卡分散到不同阵营，玩家选 2～3 个阵营时自然同时拿到"写"和"读"，组合是白捡的。发现组合本身就是乐趣，不靠系统提示去凑。

**6 条轴**（每条至少 5 张卡、至少分布在 3 个阵营）

| 轴 | 含义 | 示例（阵营 · 卡名 · 读写） |
| --- | --- | --- |
| ① 生命 | 自残换强度 | 深渊「血誓」开场扣 20% 生命转护盾【写】；荒野「困兽」生命低于 50% 攻击力 +X%【读】；元素「余烬契约」生命越低技能增强越高【读】；神域「殉难」生命低于 30% 时受到的治疗 +X%【读】；文明「背水」生命低于 40% 护甲 +X【读】 |
| ② 护盾 | 生成与消耗 | 神域「圣盾」开战获得护盾【写】；文明「壁垒」有护盾时减伤【读】；元素「盾爆」护盾被打破时对周围造成魔法伤害【读】；深渊「噬盾」有护盾期间攻击附带额外伤害【读】 |
| ③ 魔法 | 蓝量赌注 | 神域「溢流」治疗同时回蓝【写】；文明「超载」技能耗蓝翻倍、效果 +X%【写】；元素「枯竭」魔法越高技能增强越高【读】；深渊「献祭」魔法低于 20% 时攻速 +X【读】 |
| ④ 充能层数 | 积攒与引爆 | 荒野「嗜血」每次普攻叠 1 层【写】；深渊「引爆」消耗全部层数造成范围伤害【读】；文明「纪律」满层时额外获得护甲【读】 |
| ⑤ 召唤物 | 数量与献祭 | 荒野「兽群」开战召唤 N 个单位【写】；深渊「祭品」召唤物阵亡时为英雄回复生命【读】；文明「军团」每个存活召唤物提供攻击力【读】 |
| ⑥ 控制 | 施加与利用 | 元素「霜缚」技能命中附加减速【写】；文明「集火」对受控目标伤害 +X%【读】；荒野「猎杀」对受控目标攻速 +X【读】 |

**配比规则**：每条轴 ≥5 张卡、≥3 个阵营，保证玩家无论选哪 2～3 个阵营都能碰到至少一条完整轴，搭配不会落空。6 条轴合计约 30～35 张卡；不参与联动的功能卡（场地卡、纯数值卡）另计。

**UI 成本几乎为零**：不做联动规则表、不做联动预览、不做"已激活 N 条联动"的计数。只在卡面用**一个小图标**标出它关联哪条"量"（6 个图标），玩家靠图标配对，其余靠读卡面文字理解组合。

**适用范围与影响**：这条方向同时适用于基础卡与专属卡。§7.1～7.5 中大量纯数值卡（例如"攻速 +14"）按本方向应替换为轴上的读写卡，让卡表从"一堆属性加成"变成"一堆能互相咬的机制"。本次只记录方向，逐张重排留待后续（见 §14-13）。

**新增轴**：用户在本轮选定并细化了四条新轴——⑦节奏（时间 × 生命双读条件）、⑧死亡印记（永久集火 debuff）、⑨重生（阵亡转形态 + 全队成长、并入原⑤召唤物）、⑩施法（施法事件生成护盾/属性并回收魔法与生命）。卡表、白捡组合、风险与待确认项见 [卡牌联动轴设计 v1](CARD_SYNERGY_AXES_V1.md)；未选中的备选轴（伤口 / 转换 / 聚散 / 自污 / 场地叠加 / 分摊）见 [联动轴候选池](CARD_SYNERGY_AXES_CANDIDATES.md)。四条新轴在 100 张基础卡上的具体落位见 [基础卡全表 v1](BASIC_CARDS_V1.md)。

另有**场地流轴（以"已生效场地卡数量"为读数）**：场地卡已确认全场、可叠加、永不失效，因此场地数量天然是一个可读的量；对应的**场地流核心卡**思路草案见 [联动轴候选池](CARD_SYNERGY_AXES_CANDIDATES.md) §H。核心卡「共鸣领域」的口径已定：属性在**准备阶段（开战前）生效**、**只有 Lv3 才给全属性**（Lv1 / Lv2 不给，只给 +20% / +35% 增幅）、计数按张数上限 **5 张**、增幅按携卡英雄主属性合计（500 点 = +50%）。

## 9. 叠加与上限

**本节为旧 demo，不是已确认的效果上限。** 卡牌效果与阵营羁绊、八类羁绊的叠加关系仍未定案（`FACTION_COMBO_BUFFS.md` §7-1 与 §7-5）。以下数值仅保留供后续设计参考，不能据此截断正式效果或判断联动强弱：

| 效果组 | 规则 |
| --- | --- |
| 卡牌攻击伤害 | 加法，最多 +30% |
| 卡牌攻速 | 加法，最多 +50 |
| 卡牌移速 | 加法，最多 +18% |
| 卡牌技能增强 | 加法，最多 +25% |
| 卡牌造成/受到伤害 | 同一伤害事件合并，最多 ±20% |
| 卡牌护甲 | 加法，最多 +12 |
| 卡牌护盾 | 每目标所有卡牌护盾合计不超过开战最大生命的 30% |
| 卡牌治疗增幅 | 加法，最多 +35% |
| 场地卡 | 同名不可能重复；不同场地卡各自独立结算，但所属效果组仍受上表约束 |

叠加规则不改写 Dota 原生装备与技能。卡牌追加伤害采用 `card_secondary` 等来源标记的思路可保留，但“禁止所有其他卡连锁”只是旧防递归草案，正式事件规则应区分合法联动与自我重复触发；不能因此禁止生命、护盾等状态被其他卡读取。

## 10. 与阵容、敌情和技能条件的关系

- 卡牌不覆盖玩家规则，不自动更换技能顺序或强迫集火。
- **消耗卡的条件复用现有条件系统**（`condition_registry` / `target_selector`），玩家在准备阶段配置"什么条件下触发哪张消耗卡"，战斗中自动执行，不在战斗中弹出手动操作。
- 场地卡与条件系统无交互：由开战事务生成与清理，不由规则触发。
- 换人、卖出后受影响卡退回卡库并提示重新分配；不吞卡、不静默转移。
- 战斗中英雄死亡不转移效果；复活后持续效果只保留原定到期时间。

- 文字、图标、等级方块同时表达；颜色只作辅助。中英文同步。

## 12. 数据与实现

```text
scripts/data/hero_factions.json   英雄 → 阵营
scripts/data/cards.json           基础卡：id、阵营、类型、各阶效果
scripts/data/hero_cards.json      专属卡：id、英雄、普通/特殊、绑定技能、各阶效果
scripts/data/endless/*.kv         生成的运行时数据
```

运行时状态：卡库（卡 id → 累计份数 / 拥有等级 / 加值）、英雄槽位占用及所选装载等级、各阵营点数、本波剩余购买次数、本场快照（装载等级、COST、受益对象、消耗卡剩余次数及其计数范围、场地实例）。**客户端不能指定卡牌效果数值、拥有等级、槽位合法性、点数或抽卡结果**；所有请求只表达操作意图，由服务器校验 `run_id`、波次、准备阶段、实例归属与资产唯一性。

装载等级由客户端提交选择意图，服务器校验准备阶段、整数范围 `1..拥有等级`、装备资格与总 COST；效果数值与 COST 由服务器按所选档位计算。抽到重复卡只提升拥有等级，不自动改动已选档位。

开战事务沿用无尽模式的全有或全无流程：校验阵容、卡槽、装载等级与总 COST → 生成卡牌快照 → 向合法友方应用 modifier 与场地 → 创建 `battle_id` → 进入战斗。应用失败则移除本次已加效果并停留准备阶段，不扣命。

## 14. 待确认项

容量补充：**已装备卡不占卡库容量已确认**。卡库已满时卸卡、换人或卖出英雄导致的退卡，以及购买新卡的处理仍待确认；不能因容量不足吞卡。此处不预设阻止操作、临时超额或其他处理方案。

1. **装备购买是否占用那 3 次**。当前按字面理解：**只算"买英雄 + 买卡"，装备不限次**。如果装备也要占，前期会非常紧，需要重算经济。
2. **超上限加值的属性口径**——已确认是**占位值**，不是定案。机制结构（Lv3 后每多一份 +1 加值、装备时生效、本局永久、有上限）已经确定，只有"每点换什么属性"待定，备选口径与注意事项见 §6.2。**注意不要给百分比/乘算类属性**，99 层会被放大失控。
3. **付费刷新是否占一次购买**。当前假设**占**（否则限制形同虚设）。刷新价格本身就是关键旋钮。
4. **招募当波特殊卡是否立刻进报价池**。当前假设不重roll，从下一波开始出现。若手感太顿，可改为招募后立即替换报价中的一张。
5. **购买次数是否还要再放宽**。3 次下招满 8 人需要 3 波，开局已经不算干。若仍嫌慢，更精准的做法是"英雄招募不占用这 3 次"，而不是把总额度继续抬高（抬高会同时加速整条卡牌成长线）。
6. **抽卡单价**。仍是占位值 100 金。无尽版经济照搬战役基线（为 5 人上阵设计）且未按 8 人重算，**这个数字是全局最关键的刹车**，必须先定波次收入。
7. **消耗卡的触发条件由谁给**。当前假设复用现有条件系统、由玩家配置。若要"抽到就能用"，需要为每张消耗卡内置默认触发条件，会削弱条件系统的价值。
8. **场地卡作用域与生命周期——已确认**：覆盖**全战场**（无范围、无落点，不需要「固定落点」改造）；**不同场地卡可叠加**；**永不失效**（装备者阵亡、复活、换人都不影响）。因此场地层是最可靠的一层，没有"击杀携带者解除场地"这种反制，强度刹车只剩 Lv 数值、通用槽机会成本与 §9 全局上限；20 张场地卡建议统一走**顶级 COST 档**（1/8/20）。以场地数量为读数的**场地流轴与场地流核心卡**思路见 [候选池](CARD_SYNERGY_AXES_CANDIDATES.md) §H。核心卡「共鸣领域」的关键口径已定：**属性加成在准备阶段（开战前）生效**（装备即加、开战冻结、形态与幻象不另行施加）、计数**按张数**且上限 **5 张**、**全属性只有 Lv3 才给**（+20×5 = +100；Lv1 / Lv2 不给属性）、增幅算式 = **出场且装备了场地卡的英雄主属性之和 × 0.1%**（全才取最高，500 点 = +50% 封顶，阈值保留）。
   补充：场地效果**没有使用者**（不归属装备者），英雄自己的技能回血不会被自己装备的场地卡放大；「按**携卡英雄主属性合计**提高场地效果」（500 点 = +50% 封顶）是单向关系，只作用在场地层。
9. **加值只给基础卡，专属卡只走熔炼**——已定案（见 §6.2）。这是有意的分工：基础卡是可以规划、可以养长的通用件；专属卡是绑定某个英雄的一次性战术件，它的出口是熔炼成阵营点数，而不是无限变强。
10. **COST 按装载等级计费，分档框架保留**（见 §2.1）：普通 1/5/10、强力 1/6/15、顶级 1/8/20。160 张卡全是 demo，应先设计正式全友方效果，再逐张定档与验证节奏；旧装载量测算不是已验证的成长承诺。
11. **上限口径已定为全队共享**（上阵英雄等级之和），不是每名英雄各自限额。拥有等级与装载等级分离，玩家可将高等级卡按低档使用；自动升级不会强迫玩家提高 COST。
12. **无尽版必须有自己的波次经验曲线**。当前 `ENDLESS_MODE_DESIGN.md` 的"31 波起沿用第 30 波奖励档位"会拿到 `xp_pool = 0`，英雄等级停滞、COST 上限冻结。这是 COST 机制能不能在中后期生效的前提，优先级高于 COST 本身的数值设计。
13. **联动方向已定，但卡表尚未按它重排**。方向见 §7.6：不做联动规则表，改为让卡操作同一条"量"，同轴卡分散在不同阵营。§7.1～7.5 的 100 张基础卡与 §8 的 60 张专属卡都还没按 6 条轴重排——现在卡表里大多数是纯数值卡，联动实际还不存在，这是本系统当前最大的未落地项。**基础卡部分已出草案：[基础卡全表 v1](BASIC_CARDS_V1.md)**（100 张按轴重排，72 张带轴 + 28 张纯功能卡，全部三档数值）；**专属卡 60 张仍未重排**。
