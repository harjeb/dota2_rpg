# UI78：条件组合独立开关

“条件设置”中的 **使用条件** 与 **目标筛选** 各有一个独立的 **同时满足 / 按优先级** 选择器。不是技能启停，也不是下面的“目标排序”。

- **同时满足（默认）**：所有已填写条件必须满足；目标筛选要求同一个候选目标同时满足所有筛选。
- **使用条件 → 按优先级**：从上到下尝试，第一个满足即允许继续（有序 OR）。例如“自身生命 ≤ 30%”或“自身魔法 ≥ 80%”。
- **目标筛选 → 按优先级**：采用从上到下第一个存在合法可用目标的筛选组，再在该组内使用既有的第 1、第 2 项目标排序。例如先找“生命 ≤ 30%”，没有则找“生命 ≥ 80%”；组内仍可按最近或最远排序。不是把所有匹配者混在一起排序。
- 空槽不加限制，整个组为空也不限制；非空组全部不匹配则本规则失败。两个组的模式互不影响。
- 原生目标合法性、单位施法过滤、地点施法过滤、向量构造及原有射程/允许接近约束仍然生效。优先组只有非法目标、不可用落点或无法在当前策略下施放时，会尝试后续组，不会让非法候选挡住合法回退。
- 无目标技能检查触发候选，仍然下达无目标命令；向量和持续移动沿用对应执行路径。持续移动原有 Buff/启动技能事件、持续时间和锁定/重选目标规则不变。特殊残影目的地在选定组内仍使用目的地原有排序。

## 保存与兼容

顶层字段为 `use_conditions_mode`、`target_filters_mode`，值为 `all` 或 `priority`。UI 草稿、平面事件、Lua 规则、公共英雄快照和网络表均保留这两个字段。旧规则缺失字段或未知值安全按 `all` 处理；后端竞技场 JSON 对显式未知值也归一为 `all`，旧文件缺失字段时保持原形状以兼容已有哈希。

“应用”才保存，取消不改变原规则；刷新能力信息、重新打开、深复制、竞技场导出/导入均保留模式。切换技能继续使用该技能推荐条件，但保留两个组合选择；清空条件不更改组合选择。原生能力校验仍在，AND 条件冲突检查不会错误地把 OR 组当成同时成立。
