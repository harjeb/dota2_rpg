# 永久历史排行榜

游戏只保留历史总榜，不按赛季重置。积分榜包含红心耗尽的失败和全程通关；速通榜只包含从第 1 关连续推进到第 30 关的全通。每名玩家在每张榜上保留一个最佳成绩，同时保存每次终局记录和当时的玩家名称。

## 计分 v1

设 `H` 为剩余红心（0–5），`S` 为通过关数（0–30），`R` 为各关胜利时剩余时间之和（毫秒）：

```text
基础乘区 = floor(100000 × (1 + 1.1 × H / 5) × (1 + S / 30))
时间加区 = floor(R / 1000) × 10
通关加区 = 全通时 1000000，否则 0
总分 = 基础乘区 + 时间加区 + 通关加区
```

红心归一化增幅为 110%，关卡为 100%，两者相乘。通关奖励保证当前 5 心、30 关、每关 120 秒的范围内，所有全通高于所有未全通。完美成绩为 1,456,000 分。计分版本为 `hearts-stages-v1`，后端会核对原始指标并重新计算总分。

速通时间遵循本项目约定：**每关胜利时剩余时间之和，越小排名越高**。它不是实际耗时。失败尝试的时间不计入这一指标，胜利恰好剩余 0 毫秒有效。另存的全程耗时从首次开战到终局，包含重试和中间准备阶段，不参与速通排名。

## 结算与记录

终局弹窗显示分数拆分、红心、通过关数和两张榜的个人最佳成绩排名。排名与破纪录标志在后台接受提交的同一事务中捕获，因此显示的是提交时名次。全服纪录须严格优于原榜首，个人纪录须严格优于自己的原记录；首次上榜单独祝贺。相同成绩不覆盖先前记录，同值由较早达成者优先。

每次终局只生成一次提交 ID，网络重试复用同一请求；重开后旧回复不会弹回新局。终局面板不会自动消失，普通单关奖励仍保持原有自动关闭行为。同步失败时保留本地计分并说明状态，不显示虚构名次。当前重试最多 4 次，游戏进程退出后不会继续重试。

编辑器、作弊、技能调试和手选关卡属于练习，不提交到正式榜。SteamID64 从服务器取得的 Steam 账号 ID 按十进制位计算，避免 Lua 浮点数精度丢失；客户端不能提供计分数据或提交密钥。

## 服务和配置

公共服务地址：

`https://dota2-rpg-leaderboard-api.dota2-rpg-leaderboard-worker.workers.dev`

- `GET /health`：健康检查。
- `GET /api/v1/leaderboards/score`：积分榜。
- `GET /api/v1/leaderboards/speedrun`：速通榜。
- `GET /api/v1/players/{steam_id}`：该玩家最佳成绩和历史。

查询支持 `limit`（1–100）和 `offset`（0–10000）。写入只由服务器通过带鉴权的 `POST /api/v1/runs` 执行。

插件中的 `data/leaderboard_config.lua` 只保存公开地址、版本和密钥盐，不包含秘密。私有服务器可在 Dota 安装目录的 `game/dota/cfg/rpg_leaderboard.kv` 配置 `Leaderboard.submit_key`，须与 Worker 的 `SUBMIT_API_KEY` 一致。该文件在插件目录之外，不能打入创意工坊包。

官方专用服务器走 `GetDedicatedServerKeyV3("dota2_rpg_leaderboard_v1")`。正式发布前必须取得该插件在官方服务器上的真实密钥并配到 Worker；本机生成的外部配置不会自动出现在 Valve 服务器上，Cloudflare 登录授权也不包含 Valve 密钥。切换密钥时要同步所有自行托管服务器。不得把生产密钥写进插件、客户端事件、公共日志或 Git。

Cloudflare 后台源代码与运维文件位于本机 `backend/leaderboard-worker/`，按项目要求不提交到 Git。迁移、部署和运维说明保留在该目录的 README。

## 验证边界

离线回归执行实际 Lua 计分/提交模块和真实 Panorama XML/JS 的面板替身；后台测试使用 SQLite 执行迁移及事务。另以远程 Worker + D1 验证写入、重复提交、榜单、历史和鉴权，再清理仅属于验证的记录。Dota 资源编译器检查 UI 资源；这些验证不代替官方专用服务器的完整实机对局。
