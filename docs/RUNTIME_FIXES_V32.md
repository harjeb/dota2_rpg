# UI32：小小投掷目标校验与原生重生权限

本次修复小小投掷被 CUSTOM 目标掩码错误拦截，以及关卡复活禁用设置与骷髅王/不朽盾原生重生的冲突。两项都来自用户保留的 UI31 调试现场。

小小的“被抓单位是敌方”条件已保存并运行，但通过条件后，投掷被目标校验错误拦截。本次将 `tiny_toss` 加入已核实的 CUSTOM 目标掩码适配，仅把它的 CUSTOM 阵营和类型转换为双方英雄/普通单位，供选目标与提交指令前的校验共同使用。

## 当局证据

[战斗日志摘录](diagnostics/tiny-20260910/console-excerpt.txt)记录 2026-09-10 22:41:44 保存成功的规则：投掷、敌方最近、英雄/野怪/召唤物、仅施法范围内，以及第 4 个使用条件 `tiny_grab_is_enemy`。没有额外目标筛选。

22:41:46 刚开战距离较远，返回 `use_condition_failed:tiny_grab_is_enemy`。22:41:47 靠近后，返回原因变为 `no_legal_target`，此时使用条件已通过。随后仍有普通攻击指令，但投掷持续被判定为没有合法目标。

[只读原生查询](diagnostics/tiny-20260910/native-filter.txt)确认：

- 原生 `tiny_toss` 阵营掩码为 CUSTOM（4），单位类型为 CUSTOM（128），flags 为 0，没有可调用的 `CastFilterResultTarget`。
- 对敌方普通测试怪，直接把 CUSTOM 掩码传给 `UnitFilter` 得到 `UF_FAIL_ENEMY`（2）。旧 ActionAdapter 返回 false，旧 TargetSelector 留下 0 个目标。
- 对同一个真实测试怪，使用双方（3）/英雄与普通单位（3）掩码，`UnitFilter` 返回 `UF_SUCCESS`（0）。

查询发生时，用户已经退出并重新开启调试局，小小已换为实体 282，投掷为 0 级；该快照用于核实目标掩码，不能用于推断之前实体 228 的学习等级或施法距离。没有提交施法、移动、升级等指令，也没有修改运行中模块、启动或停止游戏。

## 修复范围

`native_targeting.lua` 的共享转换增加小小投掷，live 与 overlay 保持一致。转换仅针对 CUSTOM 字段；普通阵营/类型掩码、原生 flags 和可用的技能自定义校验仍然保留，其他未审查 CUSTOM 技能继续保持原逻辑。

“抓谁”由抓取半径内实际最近的候选单位决定，“扔向谁”由规则的目标与排序决定。没有近处抓取对象、最近是友军而条件要求敌军、候选等距无法明确判断、落点超出施法范围等情况仍会阻止施法。没有添加“必须另有第二个敌人”的条件，也没有把 PA 的自身目标禁用策略套到小小上。

本机原生 VPK `scripts/npc/heroes/npc_dota_hero_tiny.txt` 声明 CUSTOM 阵营/类型及 `grab_radius=300`；`resource/localization/abilities_english.txt` 描述抓取最近的友方或敌方单位，投向目标单位或符文；`resource/localization/dota_english.txt` 的小小挑战明确包含将敌方英雄投向友方英雄。上述数据未明确证明“抓取对象与落点是同一个单位”或“小小自身作落点”的真实施放结果，本次没有以此推断额外限制。

原生说明还提到减益免疫单位可作落点、不能被投掷。现有抓取逻辑与普通 UnitFilter 对这一边界仍需单独核对，跟踪 `dota2_rpg-tco`；符文不在当前英雄/野怪候选池内。本次修复针对日志中的普通测试怪目标，不宣称投掷所有原生目标机制均已覆盖。

## 骷髅王重生现场与修复

[原始日志摘录](diagnostics/wk-20260910/console-excerpt.txt)显示：22:53:17 开战并提交 `skeleton_king_reincarnation` 指令；22:53:18 骷髅王死亡，敌方目标失效。此后战斗时钟继续走，敌人一直没有合法目标。22:55:18 已进入结算，22:55:20 调试模式自动重置；重建前的骷髅王实体 137 仍为 `alive=false`。因此，这次现场是重生没有完成，120 秒截止与后续重置确实执行了。

[重置后的只读快照](diagnostics/wk-20260910/state-after-timeout.txt)显示，新的骷髅王实体 272 已恢复为存活状态，`GetRespawnsDisabled()` 为 true，全局 `IsHeroRespawnEnabled()` 为 false，已学习重生的 `reincarnate_time` 为 3。源码也在初始化和准备英雄时设置这两层禁用。该快照不是旧实体死亡期间的状态，不能用来声称已直接测到旧实体的原生重生标记或倒计时。

新增共享 `battle/respawn_policy.lua`，按当前双方阵容的实体引用管理权限：

- 全局允许英雄复活；准备英雄、待命英雄和指挥官仍禁止复活。
- 正式开战后、解除准备限制前，允许双方在场存活英雄的原生复活。
- `entity_killed` 首先检查原生 `IsReincarnating()`：战斗内重生保持允许，普通阵亡立即禁用。判断不依赖英雄名字或死亡后可能已经消失的不朽盾物品。
- 原生复活的 `npc_spawned` 保留原实体和技能、装备、冷却状态，不重新执行备战初始化。
- 普通结算、BattleManager 停止、调试重置/退出都会禁用全部在场英雄的复活，包含仍在等待重生的死者。结算后迟到的复活事件会受到停止、无敌和禁行动约束；首次备战出生不会因此失去摆位能力。
- 每个实体的原生调用单独保护，一名英雄调用失败不会中断其余英雄处理。死亡/复活日志记录原生重生标记、实际禁用状态、全局开关和剩余复活时间。

没有通过固定三秒计时器或 `RespawnHero` 模拟重生。已有 120 秒先判负规则保持不变。本机 API 说明将全局开关描述为控制普通 Dota 复活规则，单英雄开关描述为阻止该英雄复活；它们的独立作用、死亡事件中的原生标记时序及设置禁用后能否取消已排队复活，仍需新版本原生验收。已有日志证明了禁用配置和未完成复活的现场，不代替修复后原生复活成功的证据。

## 验证

新增 `tests/tiny-toss.test.lua` 使用真实规则解码、条件注册、完整战术引擎、目标选择和动作适配器，模拟当局 CUSTOM 掩码与单位，捕获最终投掷指令。覆盖单目标规则、抓取与落点分别选择、最近友军、没有抓取对象、等距候选、保护对象、范围、死亡/无敌、技能自定义拒绝、冷却/未学习，以及普通掩码和其他 CUSTOM 技能不受影响。

重生回归覆盖真实开战、死亡、出生与结算入口，共 12 个场景；包括双方骷髅王、不依赖物品栏的不朽盾状态、后续普通死亡、实体引用隔离、备战摆位、结算后迟到事件、终局以及单个原生 setter 失败。调试后端共 16 个场景，新增断言在任何清理或移除实体之前，结束、超时、重置和退出都已禁用仍然死亡等待的英雄。将旧版本 root 模块注入新测试，会在“解除准备限制之前必须允许复活”的断言失败；这些测试中的原生事件和权限效果均为模拟。

将修复前的投掷共享模块注入同一测试，会稳定失败于 `no_legal_target`；修复后的测试通过。两项改动完成后，完整 `python dota2_rpg_issue_fixes/tests/run_checks.py` 与 `tests/verify-addon.ps1` 均通过，日志位于临时目录 `dota2_rpg_v32_checks.log` 和 `dota2_rpg_v32_verify.log`。

模拟指令测试不能代替原生施放与落地验收。实现任务 `dota2_rpg-cwi`、`dota2_rpg-2fy`，重载后的实战验收 `dota2_rpg-6qv`。运行标记 `rpg-runtime-v32-20260910`，界面版本 32；正在运行的旧局需要重新载入地图才能使用新 Lua 模块。
