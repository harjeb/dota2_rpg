# v21：装备出售入口

日期：2026-09-09。运行标记 `rpg-runtime-v21-20260909`，界面版本 21。

## 功能

装备区域为当前英雄的每件装备增加“出售”，公共库存也增加“出售”。覆盖上阵英雄、待命英雄，以及物品栏、背包和原生储藏栏 0–14 号槽位。公共库存出售不需要先选英雄；原有装备、卸下和经验卷轴操作保留。

准备阶段点击出售后，按钮按物品实体锁定，显示处理状态。结果显示售出及实际到账金币，或原生不可出售、正在结算购买、物品已不在该持有者处等失败原因。失败回复后可以重试，战斗和结算阶段禁止出售。

## 原生交易与保护

之前有效代码只允许原生出售订单，没有项目面板出售入口，也没有调用原生 `SellItem` 的交易包装。原生无单位订单虽然找到持有者进行验证，却没有将持有者补入真正的订单。

新增 `issue_fixes/item_sales.lua` 及 `rpg_item_sell` 监听。服务端要求引擎提供的 PlayerID 与本局玩家一致，核对准备阶段、确切物品实体和名称、请求中持有者的当前真实持有关系，并检查原生 `IsSellable`。随后绑定合法载体的玩家归属，调用实际持有者的 `SellItem(item)`。

退款由 Dota 原生接口决定，包含其购买后退款窗口、充能和物品限制。代码不按固定半价计算，不修改购买者或购买时间，也不额外调用 `AddGold`。只有原物品实体已被原生接口删除才报告成功；仅 `pcall` 成功但物品仍存在会报告失败。原生不可出售的物品不会被强制回收。

成功后同步真实库存和 `PlayerResource` 钱包，并把本次调用前后观察到的实际金币增加传给客户端展示。客户端不自行加钱。同名物品按实体 ID 区分，已删除实体的重复请求拒绝；UI 以请求编号匹配回复，旧回复不会解锁新的出售请求。

购买扣款的核对依赖原生钱包变化。两个出售入口都会阻止在未确认购买扣款时卖出，避免退款掩盖扣款，触发购买的补扣逻辑。完成核对后出售可继续。

原生右键出售继续使用已有的玩家、阶段及持有者检查；无单位的出售指令现在会补上实际持有者。已有明确来源且持有关系正确的指令保持原路径。
