# 独立无尽模式：需求与设计 v0.1

状态：设计草案，尚未实现。本文中的首轮数值是调试起点，不代表已验证平衡或用户已确认。

新增玩法方案：[五类英雄与战术卡牌模式 v0.1](TACTICAL_CARD_MODE_DESIGN.md)，包含三档卡牌稀有度、无需拥有对应英雄即可使用的英雄卡、上阵专属加成和战败战术点补偿。该方案的初版原型不叠加本文八类被动羁绊与随机词缀；两份文档保留各自范围，均不代表已实现。

开发分支：`feature/endless-mode`。
基线：`feature/arena-seven-battles` 的 `49d3682e70e1c6a4eb84bb0d83124687ee64b57f`（UI97）。
本次交付仅创建分支、编写设计、登记 beads 工作项，不安装、不发布、不修改玩法。

## 1. 已确认范围

- 新增无尽玩法，包含敌方随机词缀和玩家阵容羁绊。
- 与当前版本隔离，当前闯关、竞技场、商店、装备、技能条件等功能保持现状。
- 按独立 addon 路线设计，先在开发分支推进。
- 本阶段排除存档与排行榜：不做继续上次对局、跨局成长、成绩持久化、排名、账号服务或后端接口。
- 本局金币、阵容、波次和随机结果只保存在运行中的服务器内存。客户端重连可重新获取仍存活的服务器状态；服务器结束后全部丢弃。

首版定位为单人 PvE。玩家通过招募、装备、站位、条件规则和羁绊构筑，挑战逐渐增强的敌军，直到生命耗尽或主动结束。

## 2. 隔离边界

Git 分支只隔离开发历史，不隔离已安装资源。因此实现时必须同时隔离 addon 身份、构建产物、安装位置和发布目标。

| 项目 | 当前版本 | 无尽版本目标 |
| --- | --- | --- |
| addon 名 | `dota2_rpg` | `dota2_rpg_endless` |
| 游戏源码/安装目录 | `game/dota_addons/dota2_rpg` | `game/dota_addons/dota2_rpg_endless` |
| 内容源码/安装目录 | `content/dota_addons/dota2_rpg` | `content/dota_addons/dota2_rpg_endless` |
| 入口 | 当前闯关/竞技场入口 | 独立无尽首页，不接入旧模式选择器 |
| 数据、地图和 UI | 当前包内资源 | 新 addon 自包含资源，不依赖旧 addon 挂载 |
| 安装 | `scripts/install-addon.ps1` | 新建专用安装脚本，只能写入新 addon 目录 |
| 发布 | 当前创意工坊条目 | 如需发布，使用独立条目；本次不创建或上传 |
| 网络服务 | 保持已有行为 | 无存档、排行、竞技场上传和配置导出请求 |

新 addon 初始复用基线的战斗、AI、商店和英雄修复代码副本，固定来源提交；不在本轮重构旧版共用底层。后续修复通过明确审查的移植同步，不自动跟随旧版更新，也不把新玩法反向合入旧版。

安装脚本需先检查目标 addon 名、规范化后的目录和资源清单，再复制。拒绝指向旧目录、通过链接解析到旧目录或覆盖旧发布元数据；卸载也只能删除新 addon 自有目录。新版本资源不能通过绝对路径引用旧 addon。原生 Dota 资源仍可复用。

版本号由新 addon 独立管理，界面交付时仍须同步更新新包中英文 `dota2_rpg_build_tag` 并核对安装副本。本次纯文档不递增 UI97。

## 3. 首版核心循环

```text
无尽首页 → 创建本局 → 生成本波敌情 → 准备阵容
                                  ↓
                           校验并开始战斗
                                  ↓
                  胜利：结算一次 → 下一波准备
                  失败：扣一命 → 本波重新准备
                  生命归零/主动结束 → 本局总结 → 新开一局
```

首轮规则建议：

| 规则 | 初始方案 |
| --- | --- |
| 阵容 | 最多 5 名英雄，招募与替补体系继承基线行为 |
| 开局经济/英雄成长 | 从基线复制为新 addon 独立配置，首轮不另改起始金币和等级规则 |
| 生命 | 初始 5 点；战败扣 1 点；首版无额外生命奖励 |
| 重试 | 保留战前资产及准备阶段交易结果；敌方阵容、词缀、奖励候选不重抽 |
| 波次 | 从 1 开始，无第 30 波通关结局；每 5 波精英战，每 10 波 Boss 战，Boss 优先 |
| 准备 | 手动开战，无强制倒计时；允许换阵、购装、配条件与查看敌情 |
| 战斗结束 | 沿用经验证的死亡/复活判定；首轮单场上限 180 秒，超时按失败处理 |
| 主动结束 | 展示本局已通过波数、耗时和阵容；不上传、不保存 |

重试以最近一次成功开战前的资产快照为边界：恢复金币、经验、物品槽位及充能、英雄配置，撤销失败战斗中的收入和消耗；准备阶段已完成的买卖不撤销。战败不发通关奖励。胜利时保留合法战斗资产变更并只发一次波次奖励。换波/重试的补血、补蓝和冷却重置沿用新 addon 冻结的基线政策。

买活等规则若沿用基线，买活冷却等反滥用计数独立于资产回滚，不因重试恢复；按实际开始的战斗计次。同一战斗重复按钮或重复回调不得重复扣命、发奖或推进冷却。

## 4. 波次与难度

### 4.1 敌群生成

采用经过验证的敌群模板池，不直接随机拼接任意技能。模板声明职责、单位数量、等级、装备档位、站位、固定机制和词缀排除。

- 普通波提供物理、法术、控制、治疗等不同组合；连续普通波避免完全相同模板。
- 精英波突出一个核心单位；Boss 波使用 Boss 加护卫，避免只有一个单位却要求多单位词缀覆盖。
- 敌军正式战斗单位首轮上限 8 个；召唤物沿用独立数量与存活管理，不能靠无限增加实体提升难度。
- 选择敌群只依赖局种子、波次、数据版本和已生成的模板序列，不读取玩家阵容来定向克制。
- 每波首次进入准备阶段即冻结模板、基础参数、词缀与奖励候选。调整阵容不会刷新敌情。

### 4.2 成长曲线

第 1～30 波使用独立、可审查的成长配置，可从原版相应阶段提取基础值，但不继续调用原版“30 关通关”逻辑。无尽数据不覆盖原版关卡表。

31 波起，以无尽版第 30 波对应档位的基础属性为参考，再结合普通/精英/Boss 模板倍率。令 `n = wave - 30`，首轮建议：

```text
生命倍率 = 1 + 0.05 × n
攻击伤害倍率 = 1 + 0.025 × n
护甲额外加成 = min(15, floor(n / 5))
```

技能等级、装备槽位和词缀数均有上限；不无限增加控制时长、闪避、魔抗、减伤或施法距离。数值成长与词缀成长分别配置，不在多个模块重复乘倍率。首轮不开放无限升级、装备无限强化或新增局外成长；满配后以阵容优化和战术调整挑战更高波数。

所有引擎写入值须有限且在明确配置的安全范围内，达到上限后截断并记录诊断，不溢出、不生成 NaN。技术上不承诺任意大波数；验证范围至少覆盖 1～1000 波的生成及边界，不以此作为玩法通关上限。

## 5. 羁绊

复用 [既有羁绊与词缀草案](BONDS_AND_RANDOM_AFFIXES_DESIGN.md) 中可用的效果定义。本文件对无尽版的范围、阶段与部署规则优先。

首版目标为八类羁绊：坚阵、争锋、秘仪、后阵、处决、破阵、守护、控场；每名开放英雄两个标签，2/3/5 人激活最高一档，低档不累加。具体效果数值暂引用旧草案 §4.3～4.4，进入实现前核实原生引擎语义。

- 只统计实际出战的不同英雄种类。替补、重复英雄、幻象、召唤物、支配野怪不贡献人数。
- 准备阶段实时预览；开战校验后冻结本场快照。死亡不降档，复活不重复叠加。
- 羁绊仅作用于声明的贡献者或本次上阵英雄，不自动扩展到召唤物。
- 换人必须显示获得/失去的羁绊和准确数值；商店展示英雄标签。
- 羁绊不改写玩家技能条件、动作优先级或合法施法规则。
- 最大生命、护盾、增伤等使用明确叠加规则；战后移除 modifier，不能反复写入基础属性。

旧草案中的“32 名英雄”是历史设计，不能视为当前全英雄覆盖。实现前以无尽版实际招募池为准完成标签映射及覆盖校验；有缺失时阻止构建，不静默给无标签英雄上线。

## 6. 敌方词缀

首版方向为敌人词缀；玩家英雄和装备随机词缀不在本轮范围。

### 6.1 开放节奏和预算

| 波次 | 全波最大威胁预算 | 开放稀有度 |
| --- | ---: | --- |
| 1～4 | 0 | 无 |
| 5～9 | 1 | 普通 |
| 10～14 | 2 | 普通、稀有 |
| 15～19 | 3 | 普通、稀有 |
| 20～24 | 4 | 普通、稀有、史诗 |
| 25～29 | 5 | 普通、稀有、史诗 |
| 30～39 | 6 | 普通、稀有、史诗 |
| 40～59 | 7 | 普通、稀有、史诗 |
| 60 及以上 | 8 | 普通、稀有、史诗 |

普通/稀有/史诗分别消耗 1/2/3 点。普通单位最多 2 条、Boss 最多 3 条；同名词缀最多覆盖 2 个敌人，高风险词缀可限制为全波 1 个。

无尽版不采用旧草案“必须花完预算，否则给多个单位强加坚韧”的回退方式。预算是上限，先满足标签白名单、互斥、数量限制和反制可读性，再在合法解中最大化使用预算。预算不足以合法花完时允许结余，情报显示实际使用量/上限；生成结果完全无词缀且预算大于零时记录诊断。禁止为花完预算突破规则。

### 6.2 内容范围

目标池沿用旧草案的 15 个方向：坚韧、厚皮、法术护壳、血怒、裂甲、愈合专注、护阵光环、壁垒之心、净化脉冲、墓前号令、奥术涌动、后排猎手、战争领主、再起、不竭势能。

首个可玩闭环先实现坚韧、厚皮、法术护壳、血怒四种普通词缀，验证增益、减伤、触发与清理。其余分批接入；未实现效果不得进入随机池，稀有度开放也不能引用空实现。完整首版目标仍是上述 15 种。

原型文件仅作参考，不视为已实现：法术护壳需正确消费次数，厚皮需正确接入减伤；治疗、驱散、护盾和增伤须通过原生引擎验证。旧草案的伤害顺序是语义目标，不能假定 Dota API 可任意重排护甲、格挡与伤害过滤器。

### 6.3 随机与重试

- 输入为 `run_seed + wave + data_version + 稳定敌人键/标签`，独立于商店刷新和战斗随机流。
- 敌人稳定键采用 `wave:template_slot:copy_index`，不使用实体索引；候选排序不依赖 Lua `pairs` 遍历顺序。
- 结果保留在本局内存中的当前波快照；失败、换阵、重建实体和客户端重连均读取同一结果。
- 词缀种类和归属不变；每次挑战重新初始化一次性触发次数和周期计时。
- 词缀不能继承到幻象和召唤物；特殊光环影响哪些单位必须显式定义。
- 新开一局才生成新的局种子。没有存盘、读档和离线继续机制。

## 7. 商店、资源与奖励

首轮复用基线商店操作、装备转移、升级、招募与技能条件能力，但所有价格、概率、经验和掉落表复制到无尽版的独立数据域。

- 1～30 波以基线资源节奏为调试起点；31 波起奖励档位暂固定在第 30 波档位，不随敌方生命倍率放大。
- 波次奖励只在首次成功结算时发放；重复回调、重试和重连不能重复领取。
- 随机奖励候选在生成波次时冻结，领取状态独立记录，防止界面反复请求刷新候选。
- 保留自然购装和换阵消耗；首版不新增词缀重抽、羁绊重抽、利息或无限属性购买。
- 对刷钱、消耗品、永久成长等能力逐项核实战败回滚和胜利保留语义，避免重试刷资源；无法正确恢复的资产行为须阻止发布。

## 8. 界面要求

独立首页显示“无尽模式”、新开一局和本局规则说明。玩家在 Dota 中启动对应 addon；本阶段不在旧版首页增加切换入口。

| 位置 | 展示信息 |
| --- | --- |
| 顶部 | 当前波、普通/精英/Boss、剩余生命、金币、阶段 |
| 招募/编队 | 英雄双标签、当前羁绊人数、下一档、准确效果、换人变化 |
| 敌情 | 敌人配置、词缀名称及数值、反制提示、已用威胁预算 |
| 战斗 | 已冻结羁绊、词缀状态/触发反馈、剩余时间 |
| 战后 | 胜负、扣命或奖励明细、重试/下一波 |
| 终局 | 已通过最高波、本局时长、最终阵容、结束原因、新开一局 |

说明和参数来自服务器数据，不在 JS 维护第二份数值。中英文同步；稀有度和羁绊变化同时用文字/图标表达。无排行榜、存档、云同步、上传状态或下载配置按钮。

## 9. 实现结构与生命周期

以下为目标路径，均位于新 addon 内，尚未创建：

```text
scripts/vscripts/endless/
  run_controller.lua     本局状态机、阶段和结算幂等
  wave_generator.lua     模板选择、成长和稳定敌人键
  bond_service.lua       羁绊预览、冻结、应用和清理
  affix_service.lua      合法组合、确定性抽取和应用
  effect_router.lua     统一效果归属、过滤、触发和清理
  economy.lua           奖励与资产快照/恢复适配
  state_publisher.lua   服务器快照与客户端恢复
scripts/data/endless/   独立策划源数据及生成的 KV
```

新入口仅装配无尽控制器及所需基线能力，不启动原版闯关结算、竞技场、排行榜或后台客户端。不能只隐藏 UI 而仍发送网络请求。

本局状态含 `run_id`、`seed`、`data_version`、`wave`、`lives`、`phase`、`lineup_revision`、`current_wave_snapshot`、`battle_id`、资产快照与结算标记。新事件使用 `endless_*` 命名；所有修改请求校验玩家身份、阶段和版本，客户端只能表达操作意图。

开战事务：校验阵容与敌情 → 捕获资产 → 生成羁绊快照 → 应用全部效果 → 创建战斗标识 → 进入战斗。应用失败则移除本次已加效果并停留准备阶段，不扣命。有效战斗的结果最多结算一次。

退出、重试与新局清理：移除 modifier/光环/AI overlay、销毁临时单位和粒子、注销或失效化计时器。异步回调同时校验 `run_id` 和 `battle_id`，旧战斗不能影响新战斗。

为避免无尽运行内存随波数增长，只保留当前波完整快照、最近有限条诊断和累计统计。旧波不可返回，不保留全局完整战斗历史。客户端重连恢复内存快照不等于存档功能。

## 11. 交付阶段与验收

下表是实现顺序和验收定义，执行状态统一由 beads 管理。

| 阶段 | 交付 | 验收依据 |
| --- | --- | --- |
| A 隔离骨架 | 独立 addon、资源、安装脚本、首页，断开旧服务 | 安装前后旧 addon 文件哈希一致；新包可独立启动且不请求旧服务 |
| B 无尽闭环 | 波次、五命、胜败、奖励、重试、新局 | 30→31 正常推进；重复请求不重复扣命/发奖；失败无资源套利 |
| C 羁绊 | 全招募池标签、八羁绊、预览/快照/面板 | 重复英雄不重复计数；死亡/复活不叠加；换阵预览一致 |
| D 词缀闭环 | 首批四词缀、合法预算、敌情、确定性 | 同输入同结果；换阵/重试不重抽；消费和驱散符合描述 |
| E 内容完善 | 全部十五词缀、精英/Boss 池、节点调参 | 互斥成立、反制可执行、无空实现；原生效果通过实机验证 |
| F 稳定性 | 长局、安装隔离及回归报告 | 多次重开无残留；实体/计时器无持续泄漏；旧版功能无改动 |

自动验证至少覆盖：1～1000 波生成边界、阶段边界的多种子合法性、羁绊阈值、词缀互斥/次数、奖励幂等、资产回滚、旧回调失效和安装路径保护。对固定回放夹具记录种子和数据版本。

实机验证覆盖：首次开局、30→31、多个 Boss、失败重试、买活/复活、消耗品恢复、客户端重连、主动结束与新局；检查技能条件、购买、装备转移、召唤物和词缀原生事件。离线生成到第 1000 波不能代替长局性能和难度验收。

隔离验收以基线提交对比旧版 `game/content`、旧安装脚本及发布配置，并实际核对安装前后文件。当前文档交付尚未执行上述实现验收，不表示新模式已可玩。

## 12. 可调设计项

本草案先采用五命、五人、5 波精英/10 波 Boss、2/3/5 羁绊、预算最高 8 点和 180 秒战斗上限作为首轮默认值。英雄池规模、成长斜率、奖励曲线及具体词缀数值在实现与试玩时调整，均不能改变“独立 addon、当前功能不受影响、排除存档与排行榜”的边界。
