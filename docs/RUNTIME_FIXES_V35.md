# UI35：装备转交保留实体，新增行动条件为空白

## 现场证据与原因

用户在装备面板点击装备后，库存中的物品消失，高亮英雄未获得该物品。本次读取 VConsole 初始历史，保存到本机 `C:/Users/harjeb/AppData/Local/Temp/rpg_equip_console_20260911.log`；日志确认运行版本为 `rpg-runtime-v34-20260911`。

- 第 9077–9100 行附近记录装备请求：`hero=npc_dota_hero_juggernaut`、`item=item_wraith_band`、`item_index=284`，位于 t=256.77 与 t=258.33 两条选择日志之间。客户端请求指定了剑圣及确切物品，不能将消失归因于发错英雄。
- 只读现场查询确认 `GameRules.Dota2RpgDemo.issueFixes` 已启用，实际走 `issue_fixes/inventory_transfer.lua`。该模块在转交和失败回滚时调用 `RemoveItem`；Dota 的这个 API 会销毁物品，随后向目标添加的已是失效句柄。主程序备用路径使用正确的 `TakeItem`，但安装兼容模块后不会经过该备用路径。
- 查询记录在 `C:/Users/harjeb/AppData/Local/Temp/rpg_equip_native_state_20260911.log`。查询时实体编号 284 已被引擎用于树精天赋；当前剑圣持有怨灵系带 309 和疯狂面具 310，仓库无普通物品，未发现地面装备。期间英雄已重建，当前物品不能证明原始请求成功。
- `dota2_rpg_issue_fixes/tests/test_runtime.lua` 原先把 `RemoveItem` 模拟成单纯脱离槽位；修正为销毁后，旧代码的第一个转交成功测试立即失败。主测试中的真实删除模拟只覆盖未安装兼容模块的备用路径。

同一段历史中，首次购买怨灵系带组件在自动合成后报告组件 `item-not-found`；再次购买卷轴报告 `attachment-failed-preserved`。这是原生合成后购买结果识别的另一个问题，不能把组件查找失败直接认作物品被销毁。本版仅修复确认存在的装备面板转交删除路径。

用户随后要求点击“＋”新增行动时条件为空白。HUD 原先深拷贝最后一行的完整规则，因此新行同一技能的条件窗口包含上一行全部条件；这一行为已用实际 HUD 脚本测试复现。

## 修改

- 主模块及安装覆盖包的转交和回滚均使用 `TakeItem`，确认原句柄仍有效且来源已不再持有后才调用目标 `AddItem`；保留原实体、充能、冷却和购买者。
- 依据操作后的实际持有状态判断成功，兼容原生调用执行后才抛异常、正常堆叠或合成。
- 目标接收失败时安全退回来源；无法从目标储藏栏安全取出则保留在那里。已有地面容器保持完整；双方均拒绝入栏时尝试把同一实体保留到来源位置，检查容器确实持有它。不会为回滚删除装有物品的容器。
- 增加请求、成功和失败码日志；HUD 订阅已有的 `rpg_inventory_transfer_result`，显示接收英雄或失败原因，库存仍只由服务端快照更新。
- “＋”仍默认选择上一行动及目标阵营，但创建新的空条件数组：使用条件、目标筛选、优先级全部留空；不继承接近策略、强制标记或其他动作选项。原行与新行独立，最多 32 行。
- 版本标识更新到 UI35 / `rpg-runtime-v35-20260911`。
