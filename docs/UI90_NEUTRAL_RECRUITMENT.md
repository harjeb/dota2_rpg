# UI90：野怪选择、原生收服与雷区标识

## 使用方式

准备阶段，在左侧选择上阵英雄。英雄拥有魅惑、神圣劝化、支配头盔或统御头盔时，英雄栏下方显示“野怪召唤”。每个来源列出技能/装备等级、野怪等级上限、控制数量上限及远古资格，从下拉菜单选择野怪；选择立即发给服务器保存。“不召唤”清除该来源选择。

开战后生成选中的原生中立野怪，由该英雄自动使用对应技能或装备收服。每个来源每场战斗生成一只；不是直接制造无限友军，也不会自动填满陈的所有控制名额。蓝耗、冷却、控制限制以及原生技能额外校验继续生效。同名重复装备使用主动装备栏中第一件，背包装备不参与。收服成功后采用已有召唤物战斗行为，原生持续时间、属性和归属继续有效。

选择会随英雄保留到后续关卡及上下阵实体重建；重新开始整局清除。每关实际生成时重新读取当前技能与装备，过期的等级/远古选择不能绕过校验。战斗中不能更改，候补英雄需先上阵后在左侧选择。战斗结算清理生成对象；成功收服的野怪不会仅因原主人死亡而被删除，原生转移归属仍然有效。

## 来源限制

- 魅惑：读取原生 `level_req` 和 `max_creeps`。当前定义等级上限为 4/5/6/6；装备/升级造成的运行时变化以实时值为准。
- 神圣劝化：读取 `level_req` 和 `max_units`，当前定义为等级上限 3/4/5/6、数量 1/2/3/4。远古资格取已学习上帝之手的实际 `ancient_creeps_scepter` 值，不能只按技能名中的历史 “scepter” 字样猜升级。
- 支配头盔：原生没有独立的野怪等级上限，不允许远古；统御头盔通过原生 `is_overlord` 开放远古。数量读 `count_limit`。
- 菜单筛选不能替代原生施法结果：执行前仍调用原生 `UnitFilter`，存在 Lua 目标过滤时也检查；最终以实际队伍转换确认收服。

目录含原生定义中 46 种可选野怪，包括普通与远古定义。它不是当前地图刷怪概率表；旧版原生定义是否在安装版本中完整工作仍需实机核验。关卡野怪此前被生成器重写为战役单位，因此另用保留原生中立单位类、等级、远古标记、模型和技能的别名，避免拿战役强化怪冒充原生可收服野怪。别名由 `scripts/build-neutral-recruitment.py` 与固定来源快照生成；关卡生成器保留其 `#base` 引用。

待收服对象不加入关卡胜负目标，没有金币/经验掉落，并临时禁止攻击、移动及受到伤害，防止被误打或用来刷收益；它保持中立和原生可选取状态。收服成功立即解除临时保护。失败、失去来源或超时移除待收服对象，不遗留障碍。英雄收服时暂停普通战术下令，但仍保留在其他英雄的视野观察、队伍统计和目标名单中。

## 雷区标识

扩展现有 Techies 原生对象观察器：

- 普通无神杖标识不作为伤害区域。
- 看见真实标识及其原生 thinker，并能看见施法者、确认其神杖升级时，记录 `trigger_radius` 触发范围。
- 观察到真实激活用 `_scepter` 源修饰器时，记录 `aura_radius` 激活范围；时限受剩余时间及 `minefield_duration` 共同约束，同一阶段反复观察不能刷新时限。
- 已知位置按队伍分别保存，隐藏后不追踪新位置或私有激活状态。没有把受影响单位身上的 aura 居中当作整个雷区，也没有读取原生私有移动累计量。

这是触发/激活区域的保守避让，不能精确预测敌人在移动累计阈值上触发的每一次爆炸。雷区标识具体原生 modifier 挂载对象和剩余时间 API 仍需在 Dota 核验。

## 验证范围

`LUA_BIN=luajit python scripts/test-all.py` 全量 **146/146** 通过。新增离线覆盖包含菜单保存/清空/战斗锁定/过期回执，技能等级与远古/装备资格、服务器重验、待收服对象保护和清理、真实队伍转换确认、转换后原主人死亡与被抢夺、生成器一致性，以及雷区标识的视野和阶段寿命。Lua 使用原生 API doubles，Panorama 使用 Node doubles；通过这些检查不能宣称 Dota 实机成功率。

当前环境默认 Dota 安装目录不存在，尚未完成资源编译、安装和原生验收。后续必须核验原生中立别名的创建/预载、四类收服实际效果、UI 下拉菜单布局和雷区标识的源修饰器，再核对安装后的两份语言文件均为 UI90。
