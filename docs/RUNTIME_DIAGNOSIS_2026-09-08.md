## 技能不释放

火枪的规则保存成功，战斗记录持续报告 `sniper_shrapnel / ability_unlearned`。通过本地 VConsole 执行只读诊断后，确认火枪仍有 1 个未分配技能点，榴霰弹为 0 级。默认条件本身没有阻止技能；战术配置不会替玩家学习技能。

全能骑士则是已学习的纯洁之锤被误判。实机读到：

- `GetLevel()` 为 1，非被动、非隐藏。
- `GetBehaviorInt()` 返回 `-2147483648`。
- `GetBehavior()` 返回 `137439088648`，保留单位指向、自动施法及高位行为标志。

旧适配器优先读 32 位接口，溢出后无法识别单位指向，返回 `special_adapter_required`。新 `tactics/ability_behavior.lua` 优先读取完整数值，以算术方式判断单个标志，避免 32 位转换。主动技能适配、向量目标、默认目标侧和旧战斗封装均复用它。在当前 Dota 进程中独立加载修正后的适配器，原生纯洁之锤已返回 `cast_type=unit`；该检查没有发出施法指令。

20:33:07 另出现 `rule_snapshot.lua:18 Invalid object passed to GetUnitName`：战术规则身份查询遍历敌方名单，直接调用了已被引擎删除的敌方实体。即使当前评估的是有效玩家英雄，也会因名单中的旧句柄而异常，最终中断游戏模式的定时更新。修复后保护原生名字读取；玩家规则直接使用稳定英雄键；敌人生成时分配带重复序号的稳定键，避免前一只同名敌人消失后，后续敌人的规则身份变化。新增实机错误模型回归，覆盖失效敌人、玩家查询和同名敌人身份保持。

## 钱包与装备

钱包增加独立的 `initialGold`，修复先读取原版 0 余额再连接玩家时开局金额被镜像覆盖的问题。原版正余额（包括不可靠金币）保留；无有效玩家或无法读写钱包时推迟初始化；已经花到 0 的钱包不会重新补钱。初始化时也向 GameRules 设置开局 500。

本局 20:31 的记录显示：免费招募火枪和全能骑士后仍有 500；购买三件力量手套各扣 140，依次为 360、220、80；火枪上场前后都为 80。因此本局没有复现上场清空余额，但不能仅凭模拟回归断言此前归零的完整原因。

用户随后确认金币扣除正确、装备没有交付。三笔购买记录均写 `transfer=resolved`，却没有成功添加后才打印的 `Native purchase routed`。代码检查发现多个原实体搬运路径使用了 `RemoveItem`。Dota 此方法会移除并删除实体，再交给目标英雄必然失败；失败分支却仍结束事务并报告成功。改用 `TakeItem` 保留实体，覆盖购买转交、原版储藏栏提升、装备回滚、卸下和阵容重建；真正销毁物品的路径仍使用 `RemoveItem`。附件失败会记录准确原因，并尝试将仍存在的实体放回来源。

回归模拟现区分 `RemoveItem` 删除和 `TakeItem` 分离，并拒绝添加已删除实体。验证连续三笔 140 金币的力量手套确实进入待命英雄、上场重建保留三个原实体，以及添加失败时保留物品。恢复旧删除调用后，对应回归会失败。

## 招募随机

英雄及品质抽取改用 Dota 原生 `RandomInt`；只有离线环境回退 Lua RNG，避免固定 Lua 起始序列带来的相同开局。仍为五个互不重复且排除已拥有英雄的报价，属性覆盖及固定招募价格保持原规则。实机开局 `ShopRoll` 已记录 `rng=native`；不同原生随机流的模拟验证了输出差异，尚不把单次开局当成多局随机分布验收。
