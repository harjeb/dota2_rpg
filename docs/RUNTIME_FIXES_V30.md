## 幻影突袭的目标筛选

当前原生技能返回 `GetAbilityTargetTeam() = CUSTOM (4)`、`GetAbilityTargetType() = CUSTOM (128)`，Lua 没有可调用的 `CastFilterResultTarget`。通用 `UnitFilter` 直接使用这两个 CUSTOM 值，会把敌人判为 `UF_FAIL_ENEMY (2)`。

对第 3 关实际五个敌方实体的只读查询，原值全部返回 2；改用双方英雄/普通单位掩码进行独立查询，全部返回 `UF_SUCCESS (0)`。当时它们在备战位置，距离 823–1339，不表示已经满足施法距离。

新增共享 `tactics/native_targeting.lua`，仅对幻影突袭的 CUSTOM 字段提供明确目标类型。候选选择和最终订单验证共同使用该适配，防止只修一处、另一处仍提前拒绝。其他技能与普通目标掩码保持原生含义；原生 flags、可调用的专属过滤、距离、缠绕、充能和施法状态检查仍生效。幻影突袭排除自身。

之后将仓库的新模块放进独立局部对象，继续对原生实体做只读合法性比较，没有替换运行中的引擎对象。此时游戏已到第 5 关备战，所有英雄都有备战无敌保护，普通原生筛选返回 18，新代码仍拒绝这些目标。见 [修正后备战保护读回](diagnostics/pa-20260910/patched-filter-prepare.txt)。该比较没有验证实际跳跃或施法完成。

## 首次编辑丢失其他默认行

HUD 的应用按钮每次提交一行，并附带完整行数。旧 `RuleService` 首次保存时从空权威列表开始，仅写入当前槽位；例如界面有三行，只编辑第一行后，实际列表变成一行。之后引擎采用这一行，不再执行另外两行默认规则。首次编辑第二行还可能留下首槽空洞。

现在桥接层为服务提供有效默认列表。首个合法保存先复制完整默认规则，再替换当前行，按客户端声明的行数处理删除，并同步保留行。复制包括嵌套数据，后续编辑不影响默认缓存。拒绝的保存不建立作者状态；后续保存不重新补入默认规则，用户明确删除的行不会复活。

已复现的首次保存缺陷与当前 PA 的规则状态一致，但历史编辑事件已不可恢复，不能确认本局每一步操作。修复不会猜测并改写已有非空作者列表：当前局缺少的模糊可手动添加为“模糊 → 自身”，或新局重新生成默认规则。
