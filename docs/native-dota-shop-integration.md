# 原版 Dota 商店接入与双卷轴面板方案

> **状态：用户已拍板，待实现。**
> 本文由用户在 2026-09-05 确认，优先级高于旧设计中“装备仅由自建 Panorama 商店出售”的约束。对应 Beads：`dota2_rpg-efs`。

## 1. 最终产品决定

### 1.1 保留什么

保留项目现有的 Panorama 装备区域，但将其收敛为两个职责：

1. **双经验卷轴商店**：只出售低级经验卷轴与高级经验卷轴；保留当前的限购、库存和“对当前选中的上阵英雄使用”规则。
2. **小精灵转交面板**：显示玩家小精灵当前真实物品栏，允许将其中一件物品一键交给当前持续选中的上阵英雄；也显示该英雄已装备物品，并可一键卸回小精灵。

英雄招募商店不受本决定影响。

### 1.2 取消什么

取消项目自建装备商店的以下部分：

- 固定装备目录和 `items.kv` 定价表；
- “购买并装备”“存仓购买”按钮；
- 面板中的自定义装备出售按钮和自定义 50% 回收价；
- 只允许项目白名单装备的限制。

因此，Panorama 面板不再复刻 Valve 的装备目录，也不会和原版商店形成两套普通装备价格。

### 1.3 原版商店规则

普通装备统一由 **Valve 原版 Dota 商店 UI** 购买和出售：

- 打开原版商店后，可购买该 Dota 客户端当前原版商店实际展示并允许购买的全部物品。
- 价格、合成、堆叠、冷却、充能、库存限制和出售价格均由 Dota 原版规则决定；项目不再重算或覆盖它们。
- “开放全部原版物品”指原版商店中实际可购买的物品；不把中立掉落、开发物品、隐藏内部物品或原版本就不可购买的物品伪造为商品。
- 出售使用原版商店的正常出售规则（而非项目强制的固定 50% 回收）。如果后续产品希望“原价买、原价全额卖”，那是另一项显式平衡决定，不能误称为沿用原版出售规则。

## 2. 玩家操作流程

### 流程 A：直接给上阵英雄购买

1. 在准备阶段选中一名上阵英雄。
2. 打开原版 Dota 商店（使用 Dota 默认商店快捷键/按钮）。
3. 正常购买任意原版可售物品。
4. 物品进入该英雄的原版物品栏；其主动效果会按现有动作适配规则决定是否出现在行动编辑器中。

### 流程 B：先买到小精灵，再一键交给英雄

1. 在准备阶段选中玩家小精灵（指挥官）。
2. 打开原版 Dota 商店并购买物品；物品进入小精灵的真实 9 格物品栏。
3. 在项目“卷轴与装备转交”区域选择目标上阵英雄。该目标在一次操作后**保持不变**。
4. 点击小精灵库存中该物品的“装备”按钮。
5. 服务端搬运**同一个物品实体**到英雄的 0–5 号主动物品栏；满格时拒绝搬运，不丢物品、不扣额外金币、不重生英雄。

### 流程 C：卸下、出售与原版拖放

- 点击“卸下”可把指定的真实物品实体从目标英雄放回小精灵；小精灵满格时拒绝。
- 要出售时，选中当前持有物品的小精灵或英雄，通过原版 Dota 商店出售。
- 准备阶段仍允许受控的原版拖放：小精灵/当前上阵英雄之间交付，明确持有物品可丢到地面，物理掉落物可被二者拾取。
- 战斗倒计时、战斗与结算阶段关闭购买、出售、穿脱、丢弃、拾取和交付，防止战斗中改变构筑。

## 3. 技术实现方案

### 3.1 金币：以 `PlayerResource` 为唯一权威

当前项目用 `self.gold` 驱动招募、卷轴和旧装备面板；而原版商店消费的是 Dota 的玩家金币。接入后不能维护两套可漂移余额。

实现要求：

1. 使用 `PlayerResource:GetGold(playerId)` 作为唯一金币来源，并在开局/关卡奖励/招募/卷轴消费时通过原版金币 API 修改它。
2. `self.gold` 仅作为旧代码兼容缓存，或彻底删除；任何 HUD 金币展示均从 `PlayerResource` 同步。
3. 监听 `dota_item_purchased`，并在库存快照轮询中检测原版合成、出售、丢弃、拾取等变化，随后重广播金币和物品状态。
4. 招募、刷新、替补位和两个卷轴的扣款统一走同一套原版金币读写封装，避免“原版商店买得起、项目商店显示买不起”或相反的情况。

### 3.2 原版商店启用与阶段锁

- 保留 `GameRules:SetUseUniversalShopMode(true)`，让地图无需依赖特定建筑商店位置。
- 不隐藏 Valve 默认 HUD 商店；不再让 Panorama 模拟全套普通装备目录。
- 在 `OrderFilter` 中专门处理购买/出售相关订单：即使原生订单没有常规 `units` 字段，也要按 `issuer_player_id_const` 和当前阶段验证，不能因“未找到战斗单位”而绕过锁定。
- 以真实 Workshop Tools 订单字段验证 `PURCHASE_ITEM`、`SELL_ITEM`、`DROP_ITEM`、`PICKUP_ITEM`、`GIVE_ITEM` 和 `MOVE_ITEM`。如果某个原版购买路径无法在订单发生前安全拒绝，必须采用物品入栏过滤与原子回滚；验收标准是战斗阶段既不留下物品，也不改变金币。
- 小精灵和当前上阵英雄是唯一可进行装备交互的载体；待命英雄、敌方、中立单位和任意客户端伪造目标一律拒绝。

### 3.3 实例身份与同步

- 小精灵库存、英雄装备栏和 Panorama 按 `item_name + item_entity_id` 同步；名称只用于显示，操作必须携带实体 ID。
- 购买后、合成后、出售后、丢弃后、拾取后、转交后和卸下后均重建装备快照；快照包含实体 ID，防止同名物品替换后 UI 保留旧 ID。
- 转交只能搬运同一个 Dota 物品实体，不能“删除后按名称重新创建”。这保留当前充能、堆叠、冷却以及原版物品内部状态。
- 仅在阵容重铸这种不得不销毁英雄实体的边界，按明确的状态适配器恢复可恢复的原版状态；该边界需要独立实机验证，不得假设所有自定义状态天然可恢复。

### 3.4 Panorama 收敛

保留并改名现有 `ItemShopPanel`：

| 区域 | 改造后内容 |
| --- | --- |
| 标题 | `卷轴与装备转交`，明确普通装备请使用原版 Dota 商店 |
| 目标区 | 常驻当前目标英雄头像、已装备列表、卸下按钮 |
| 小精灵库存 | 真实库存物品、装备按钮；不显示项目出售按钮 |
| 卷轴区 | 低级/高级卷轴的购买与使用，保留各自限购 |
| 普通装备目录 | 删除 |

面板应增加简短指引：**“选中小精灵，打开原版商店购买；或选中英雄直接购买。”** 不承诺用 Panorama 伪造按键来强开 Valve 商店。

## 4. 分阶段实施与验收

### 阶段 1：原版商店可用性探针

1. 在干净的 Workshop Tools 对局中确认原版商店可打开、可购买、可出售。
2. 分别选中小精灵和上阵英雄购买以下样本：普通成件、配方合成物、可充能消耗品、主动装备、堆叠物品。
3. 记录原版订单筛选字段和游戏事件负载，确认购买后物品实际进入哪个单位、原价扣款是否来自 `PlayerResource`。

**通过条件**：至少一件物品可直接买到英雄、一件可买到小精灵并由项目一键转交；原版出售金额符合客户端规则。

### 阶段 2：金币与阶段安全

1. 迁移项目金币到统一封装。
2. 移除自定义普通装备价格/购买/出售事件和 UI。
3. 为原版购买、出售、合成、丢弃、拾取、交付和移动加入准备阶段白名单。
4. 在 `COUNTDOWN`、`FIGHT`、`SETTLE` 对每条路径做拒绝与余额不变验证。

**通过条件**：任一阶段外操作都无法改变物品栏或金币；准备阶段的原版购买、出售和转交稳定可用。

### 阶段 3：转交体验与回归

1. 保留选中目标，连续给同一英雄转交多件物品，不要求重新点击头像。
2. 同名、不同充能、不同堆叠数物品按实体 ID 精确操作。
3. 英雄满 6 格、小精灵满 9 格、目标无效、物品已被合成/出售、重复点击和拖放中断均不丢物品。
4. 更新 Lua/Panorama 自动测试，并在实机验证后部署、提交和推送。

## 5. 验收标准

1. 原版商店 UI 可用，展示并购买 Dota 当前原生可售物品。
2. 原版购买价格与出售结果没有项目侧二次计价。
3. 项目面板仅出售低级与高级经验卷轴，不再展示普通装备目录、直购或自定义出售。
4. 选中小精灵购买后，一键转交给英雄；选中英雄可直接购买。
5. 连续转交不丢失目标选择；同名物品不会转错实例。
6. 准备阶段允许合法的交付/丢弃/物理拾取；其他阶段全部拒绝，金币和物品栏不变。
7. 小精灵/英雄满格、合成和出售等边界不丢物品。
8. 自动测试、Panorama 编译、Workshop Tools 实机购买/出售/转交均通过。

## 6. 对旧设计文字的覆盖范围

本文覆盖旧设计中以下结论：

- “默认 Dota 商店隐藏，不作为发布依赖”；
- “普通装备必须由自建 Panorama 目录出售”；
- “自建装备出售固定返 50%”。

其余战前自动战斗、单局 Run、无跨局存档、英雄招募、双卷轴及装备转交目标保持等规则不因本决定改变。
