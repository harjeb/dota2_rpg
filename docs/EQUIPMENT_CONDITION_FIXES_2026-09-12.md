# 装备、魔晶与条件刷新修复（2026-09-12）

用户反馈装备仍为单列、卷轴商店缺少能给目标英雄购买魔晶的入口，以及新装备条件提示刷新但没有按钮。本轮同时核查了中途出现的“发送快照错误”。

## 修复行为

- 装备页的已装备和小精灵库存改为显式双列：每行固定两个等宽单元格，奇数末项保留空单元格。尺寸不再依赖两个 50% 卡片自动换行；过滤回城卷轴后仍按实际显示数量排列。转交、卸下、出售仍携带原装备实体 ID。
- 卷轴与魔晶商店新增 1400 金币的魔晶购买。目标取自装备页所选上阵或待命英雄，经 `rpg_shard_buy` 请求交给现有服务端事务校验。客户端不传价格；服务端验证发送玩家、阶段、英雄所属、已有升级、原生价格、余额、补货及尚未完成的原版交易。直接授予目标英雄的原生魔晶升级，生效后扣款，不创建小精灵物品。成功后刷新英雄技能与商店状态；品质自带或已购买魔晶会显示“已拥有”。原生商店既有拦截保留。
- 条件设置底部恢复“刷新技能能力（保留草稿）”。调用既有服务端状态请求，在保留输入控件和草稿的情况下等待实时能力数据。匹配英雄、规则身份、动作和版本后才允许保存；旧英雄/动作/规则变化会使原弹窗失效。刷新不提交规则。
- 同步 `dota2_rpg_issue_fixes/overlay` 内的 UI 镜像，避免后续覆盖恢复旧行为。

## “发送快照错误”的证据与范围

在本机 `game/dota/pak01_dir.vpk` 中，`resource/localization/dota_schinese.txt` 的 `GameUI_Disconnect_SnapshotError` 文案正是“发送快照错误”；英文是 `Error sending snapshot`。`game/bin/win64/engine2.dll` 中也有 `NETWORK_DISCONNECT_SNAPSHOTERROR` 对应项。这是引擎同步游戏状态时的断线原因，不是排行榜 HTTP 请求的错误提示。

当前可用 `game/dota/console.log` 只记录到 2026-09-12 16:10:12，内容是工具启动，未覆盖用户报告的对局。没有此次错误前后的网络信息、实体数量或载荷大小，不能认定具体根因。引擎另有独立的 `SnapshotOverflow` 原因，不能把本次提示直接等同于溢出。

后续采集由 beads `dota2_rpg-pt4x` 跟踪：用户下一次正常启动前可在 Steam 的 Dota 启动选项添加 `-condebug`，并在复现时保留发生时间、关卡和能否重连的信息，再分析当时日志及可用的专服记录。未为缺乏证据的推测调整实体、消息或更新频率。
