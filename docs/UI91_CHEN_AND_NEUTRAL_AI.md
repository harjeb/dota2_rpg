# UI91：陈的多选野怪与收服野怪自动施法

准备阶段选择陈，在“野怪召唤”的神圣劝化栏目按名额逐只选择。名额数跟随当前 `max_units`，原生普通等级通常为 1/2/3/4。允许重复选择同一种野怪，也可留空；全部选“不召唤”清空本场计划。其他技能、装备仍为每个来源一只。

同时校验野怪等级、总数量及远古数量。远古上限读取已学习上帝之手的实时 `ancient_creeps_scepter` 特殊值；字段名保留原生历史命名，不按名称推断升级。服务器完整校验整份列表，超过任一限制不保存部分结果。界面同步后按当前合法名额显示；原保存选择仍可跨关、上下阵实体重建保留，生成前再次校验。

开战后按选择顺序依次生成并使用原生神圣劝化收服，继续消耗原生蓝量和冷却。后续名额需要等技能再次可用，**不是开战瞬间直接获得四只友军**。技能未就绪时陈仍可执行普通战术，正在收服时暂由收服控制器持有命令。不会因野怪死亡而无限补充；每场每项仅有限尝试，失败也消耗本场尝试名额。实时数量下降会停止超额生成，并取消尚未转换的超额对象；已有原生控制单位也参与容量校验。名额暂满时保留尚未尝试的选择，容量恢复后继续；同队其他英雄收走野怪后不再占用原陈的额度。

本功能生成并收服的野怪现在直接复用敌方野怪的 `EnemyRules.CreateForUnit`，根据实际技能栏创建自动施法与攻击规则。自中心范围技沿用原有半径门槛，冷却、蓝耗、施法前摇、引导、被动和自动施法处理沿用战术引擎。普通召唤物每半秒发普攻的逻辑不再同时控制这些野怪，避免覆盖技能命令。

原主人死亡不会停止仍存活野怪的 AI；被原生技能改变归属后，按当前队伍和归属重新判断敌友。待收服的中立对象不会提前加入施法 AI。本关生成对象仍在结算清理。野怪派生的其他召唤物继续沿用已有召唤物行为，本次没有新增独立技能编辑器。

验证覆盖：陈多选、重复种类、清空、实时名额变化、事件转发与整份列表校验、原生资源等待、队列推进与失败、控制上限降低、已有原生控制单位、跨实体恢复，以及收服野怪的同源技能规则、友敌切换、主人死亡、技能控制权和结算移除。`LUA_BIN=luajit python scripts/test-all.py` 全量 147/147 通过。安装编译命令因默认 Dota 路径不存在而失败，未安装或验证原生执行，后续验收记录为 `dota2_rpg-9hu`。离线测试不能证明实际 Dota 原生施法效果，仍需在游戏中检查四名额冷却顺序、远古升级限制，以及人马踩、萨特冲击波、巨魔网等典型技能。
