## Network interpretation and limits

- Gameplay signon explicitly uses **loopback**: preceding log at 22:29:33 says `server @ loopback:1`; latest log line 81 says player `@ loopback:0`. This is local client/server gameplay, not evidence of a remote gameplay server timing out.
- Search of the latest console for disconnect, timeout, snapshot, connection loss/closure, serialization and HTTP terms found **no terminal disconnect/snapshot-failure/HTTP-error sequence**. Initial lobby `DOTA_LEAVER_DISCONNECTED` entries and `DOTA_CONNECTION_STATE_CONNECTED NETWORK_DISCONNECT_INVALID` are at signon, not the crash boundary. `NetChan Setting Timeout` configures a timeout; it is not an elapsed timeout. Later `Tactic ... chase_cancelled ... reason=timeout` entries concern AI chasing, not networking.
- The crash records directly establish an invalid native memory read. Ordinary packet loss is not an adequate explanation for that instruction/context. A disconnect after process failure would be a consequence, not necessarily its cause.
- No packet capture, Steam service-health investigation, full memory dump or symbolized object inspection was performed. An indirect network/GC-triggered engine bug cannot be categorically excluded. Loopback does not mean Steam/GC services are absent.
- These crash dumps do not quantify any preceding freeze or establish a deadlock. One can diagnose the terminal exception without claiming to explain every period perceived as a hang.
