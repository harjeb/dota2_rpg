# v16：条件框、原生施法距离和五条生命

对应实现任务 `dota2_rpg-a7t`。运行时与界面版本均为 16。

## 条件选择框

v13 修改的是参数输入框，漏掉了条件选择按钮本身。`.V2Selector` 虽然宽 345px，但其中的 `.V2Button` 没有明确宽度，按钮内部 Label 又使用 `width: 100%`，形成依赖内容计算宽度的循环，可能收缩到约 30px 并将文字逐字换行。

现在选择按钮明确占满 345px 容器，高度固定为 48px，文字最多占两行；技能图标选择按钮也明确占满参数容器。数值参数仍为至少 110px 宽、36px 高。条件菜单与整个设置窗口保留纵向滚动。

原生资源编译通过；这里没有启动 Dota 或截图，不能把 CSS 编译成功当作实际像素验收。

## 破晓晨星及同类技能

破晓晨星 Q `dawnbreaker_fire_wreath` 是定向近战挥击，没有标准施法距离字段；W `dawnbreaker_celestial_hammer` 的距离在 `AbilityValues.range`（700/900/1100/1300），而不是标准字段。原生距离接口返回 0 时，旧适配器会将可选敌方落点全部判为超出距离，最终没有施法命令。

当前解析器优先采用有效原生接口，其次读取标准 `AbilityCastRange`，最后仅对核对过的技能读取相应原生参数。还有一种边界情况：基础接口为 0，而有效接口只返回以太之镜等提供的射程加成；现在不会把这个加成当成技能的完整距离。

| 技能 | 标准接口为零时的依据 |
| --- | --- |
| 破晓晨星：星破天惊 | `swipe_radius`，以第一轮挥击可及范围选择方向 |
| 破晓晨星：上界重锤 | `range`，按当前等级和原生特殊值读取 |
| 玛尔斯：战神迅矛 | `spear_range` |
| 玛尔斯：神之谴戒 | `radius` |
| 卓尔游侠：数箭齐发 | 当前攻击距离 + `arrow_range_base`，与原生说明一致 |
| 克林克兹：炽烈火雨 | `range` |
| 帕克：新月之痕 | `max_distance` |
| 马格纳斯：巨角冲撞 | `range` |
| 虚无之灵：太虚之径 | `max_travel_distance` |
| 凤凰：凤凰冲击 | `dash_length` |
| 齐天大圣：猴子猴孙 | `cast_range`；持有 A 杖时优先 `cast_range_scepter` |
| 虚空假面：时间漫游 | 保留之前的 `range` 修复 |
| 发条技师：照明火箭 | 核对过的全图施法，零基础距离不再等于只能在脚下放 |
| 先知：自然之怒 | 同上 |
| 树精卫士：活体护甲 | 同上；友方目标合法性仍由原生检查约束 |
| 风暴之灵：球状闪电 | 全图落点语义；实际移动和耗蓝仍由原生技能处理 |

定向挥击、固定轨迹和基于攻击距离的效果，不因上述后备逻辑额外扩大伤害范围。此修复不修改技能伤害、命中形状、位移轨迹或动画，也不跳过蓝量、冷却、控制状态与原生落点过滤。现有玩家条件保持原样；距离或生命门槛本身不满足时仍会等待。

检查了 `data/native_skill_conditions.json` 当前 1095 条记录。其中 19 个已覆盖表达的主动 POINT 定义没有声明正数标准距离（包括顶层为 0 的情况），16 个已按上述语义处理。其余 `legion_commander_intimidate`、`tidehunter_arm_of_the_deep`、`furion_hedgerow` 缺少原生机制说明，是否为实际可用技能及其距离含义由 `dota2_rpg-nyc` 跟踪，没有根据模糊字段猜测距离。

现有控制台日志没有破晓晨星的施法追踪，不能据此声称游戏内已成功命中。回归测试复现并修复的是完整保存规则 → 目标选择 → 原生施法命令路径中的零距离拒绝。

## 五条生命与奖励

| 累计失败 | 剩余生命 | 结算 |
| --- | --- | --- |
| 0 | ♥♥♥♥♥ | 新 Run 初始状态 |
| 1 | 4 | 重试当前关 |
| 2 | 3 | 一次性获得 2000 金币 |
| 3 | 2 | 重试当前关 |
| 4 | 1 | 一次性获得 1 个不朽盾和 1 个奶酪 |
| 5 | 0 | Run 结束，不再安排准备阶段或允许开战 |

左上角固定显示五颗心，已消耗的心变灰。整场失败、超时判负和双方全灭平局各扣一条；胜利、单个英雄死亡、换阵、换关和界面重新同步不扣命，也不重置生命或重复发奖。`DESIGN.md` 的旧无限重试描述已同步替换。

`battle/run_lives.lua` 保存本 Run 的生命与待交付物品。`EndBattle` 先占用结算阶段，再扣命和发奖，重复结束通知不能再次扣命或发奖。2000 金通过现有服务端钱包发放；界面仅显示服务端结果。

两个道具均为原生 `item_aegis` / `item_cheese`，设置可丢弃、完全共享、无购买者绑定。先交付共享仓库；原生库存拒绝时，将同一物品实体放到小精灵脚下。如果库存与地面交付均失败，保留同一实体等待重试，不额外创建奖励。现有转交/卸下流程使用 `TakeItem` 保留实体；不改写不朽盾的复活效果、原生时限或奶酪效果。

全灭判定现在将原生 `IsReincarnating()` 的英雄视为仍有复活机会，覆盖不朽盾和冥魂大帝。普通存活计数和目标选择依然只认活着的单位，战斗超时规则保持有效。
