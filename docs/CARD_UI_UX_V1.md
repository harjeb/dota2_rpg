# 卡牌 UI / UX 规格 v1

本文先围绕当前卡型建立信息架构、卡面与操作流程，保留此前卡背设计。它是中文交互规格，不代表原生 Panorama、服务端卡牌规则或真实战斗已经实现。

配套浏览器研究稿：[card-ui-v1/index.html](prototypes/card-ui-v1/index.html)，数据文件为同目录 `data.js`，由当前卡表生成。研究稿用于观察卡面、查阅三档原文和验证点击配装的信息组织；本轮设计稿可见版本为 **UI99**，按项目规则同步更新主 addon 的中英文版本标记。独立无尽 addon 的原生卡牌界面仍是既有 UI98；本轮未安装、未迁移原生界面，历史测试与部署报告保持原样。

> 后续原生交付：独立 addon 已更新至 [UI 100 原生界面](CARD_UI_NATIVE_UI100.md)，接入当前 100 张基础卡、只读图鉴和原生配装交互。上段与 §12 记录的是 UI99 浏览器研究阶段；当前源码交付与验证边界以 UI100 记录为准。

## 2. 分类与玩家心智

先分 **基础卡 / 专属卡**，再在基础卡下分 **增益 / 消耗 / 场地**。阵营是与类型并列的筛选维度；联动轴是可选提示，不另设稀有度或核心卡层级。

| 分类 | 数量与资格 | 呈现重点 |
| --- | --- | --- |
| 基础卡 | 五阵营各 20 张，共 100 张；只装通用槽 | 阵营、三种行为类型、全队收益、装载等级 |
| 增益 | 每阵营 9 张，共 45 张 | 常驻能力或卡面条件、层数与上限 |
| 消耗 | 每阵营 7 张，共 35 张 | 自动条件、次数、冷却、持续效果；战斗中不手动使用 |
| 场地 | 每阵营 4 张，共 20 张 | 全战场、持续至战斗结束、无使用者、独立共存 |
| 专属卡 | 每英雄普通 / 特殊各一张；具体新效果待设计 | 英雄绑定、普通 / 特殊入池资格；不得拿旧 demo 当正式卡面 |

每名上阵英雄严格保留 **1 专属槽＋1 通用槽**。8 人最多 16 槽，其中只有 8 个通用槽可装基础卡。议题 `kwl` 中的“三槽”属于旧描述，不成为设计依据，也不新增场地槽。专属槽只接受该英雄自己的专属卡，普通与特殊二选一；特殊卡在招募该英雄后才满足入池资格；招募当波不重抽已有报价，从下一波开始有机会出现。

英雄是携卡者、槽位提供者和团队 COST 预算来源，不自动成为效果唯一受益者。详情必须分开列“携带：英雄名”“触发观察对象”“效果对象”。通常团队增益覆盖所有合法友方，但卡面指定施法者、攻击者自身、英雄本体、敌人或装备者时依卡面处理；例如技能吸血是各自实际伤害恢复自身生命，不复制成全队各恢复一份。

## 3. 页面与信息层级

准备阶段主视图建议分为顶部概况、左侧筛选、中部卡片网格、右侧详情与下方阵容。顶部稳定显示阶段、波次、生命、金币、**未装备卡库 x/24**、本波购买 x/3、团队 COST 已用 / 上限；研究稿中演示数据需注明“样例”。

| 入口 | 内容 | 与其他页面的区别 |
| --- | --- | --- |
| 图鉴 | 当前 100 张基础卡，按阵营 / 类型 / 名称或 ID 搜索 | 图鉴不是持有列表；查看不等于获得，不把 100 算进容量 |
| 我的卡库 | 本局样例持有资产，默认只看未装备；可切换查看已装备 | 上限是 24 张未装备的不同卡；同名份数不另占位 |
| 阵容配卡 | 8 名英雄，每人两个可聚焦槽位 | 基础卡只能装通用槽；专属槽展示规则与占位 |
| 本波报价 | 5 个卡背、价格与共享购买额度 | 正式流程设计，研究稿不实现购买 |
| 熔炼 / 兑换 | 专属卡份数、各阵营点数、基础卡兑换目标 | 正式流程设计，研究稿不实现资产销毁与兑换 |
| 战斗状态 | 场地总览、增益状态、消耗剩余次数与持续效果 | 只读布局研究，不运行真实战斗 |
| 卡背 | 原有卡背的独立展示 | 查看既有视觉资源，不改变购买前可见信息 |

图鉴与卡库复用筛选布局，但计数分别写“筛选结果 12/100”和“未装备 12/24”。筛选无结果时保留筛选条件，提供“清除筛选”；卡库为空时解释尚未持有，不展示虚构卡牌。返回网格保留筛选、滚动位置和选中项。

## 4. 卡面和详情

卡面第一眼依次读到：名称、阵营与类型、当前查看 / 装载等级、核心效果、状态。COST 固定放在右上角，等级状态置于底部，避免把拥有等级当成正在生效的档位。

| 区域 | 网格卡面 | 详情展开 |
| --- | --- | --- |
| 身份 | 名称、阵营徽章＋中文名、类型图标＋中文名 | 卡 ID、基础 / 专属、专属绑定英雄 |
| 等级 | “拥有 Lv3”“装载 Lv1”分别标注；未拥有写“未拥有” | Lv1 / Lv2 / Lv3 三档完整原文；查看等级与设置装载分离 |
| 效果 | 选中档位关键效果，长文本可摘要 | 条件、对象、三档效果、持续、次数、冷却、上限及原文补充 |
| 费用 | 正式数据未定写“COST 待定” | 三条已定曲线；研究样例必须另标“普通曲线设计样例，未给此卡定档” |
| 资产 | 累计进度，如 2/3；已装备标携卡英雄 | 份数、拥有等级、装载等级、基础加值或专属可熔份数 |
| 状态 | 常驻 / 等待条件 / 生效中 / 次数用尽等文字 | 触发观察对象、剩余次数、冷却和效果结束时间分别展示 |
| 联动 | 最多一个可选轴图标 | 图标中文解释；不得从图标反推或生成触发条件 |

九个轴图标保持原编号：①生命、②护盾、③魔法、④充能层数、⑥控制、⑦节奏、⑧死亡印记、⑨重生、⑩施法。⑤召唤物已并入重生，不增设第十个图标。无轴卡不显示空插槽或“缺少联动”的负面提示；不要求某轴张数配额。共鸣领域不带轴，也不设核心卡徽章。

三档读取必须来自源卡表的完整效果，不能把 Lv1 数字乘系数推算 Lv2 / Lv3。固定数值、时间、次数、上限和额外解锁条款均需保留，例如超载三档技能增强不同但耗蓝代价始终 +20%，共鸣领域只有 Lv3 解锁场地增幅。研究稿以 `data.js` 的源文本展示全部三档，避免把通用数字拆分算法当作正式效果解析器。

## 5. 拥有、装载与预算

同名卡是全队唯一资产，只能装备在一个槽。累计 1 / 2 / 3 份解锁拥有 Lv1 / Lv2 / Lv3；准备阶段允许在 `1 ≤ 装载等级 ≤ 拥有等级 ≤ 3` 中选择。图鉴可以查看未解锁档位，但设置装载按钮要说明“需要拥有 Lv2”。获得重复份数只提高拥有等级，不自动提高装载等级、效果、次数或 COST。

| 强度档 | Lv1 | Lv2 | Lv3 | 状态 |
| --- | ---: | ---: | ---: | --- |
| 普通 | 1 | 5 | 10 | 曲线已定，各卡归档未定 |
| 强力 | 1 | 6 | 15 | 曲线已定，各卡归档未定 |
| 顶级 | 1 | 8 | 20 | 曲线已定，各卡归档未定 |

研究稿点击装载所用 **1/5/10 仅为共同的普通曲线设计样例**，应在预算旁和详情中持续可见，不能把 100 张卡全部登记为普通卡，也不能按场地身份自动登记强力或顶级。正式预算为所有已装备基础 / 专属卡 COST 合计，上限为本场上阵英雄等级总和。

推荐操作为选中卡 → 查看完整效果与拥有等级 → 选择装载等级 → 点击合格通用槽 → 显示携卡者、容量和预算变化。点击已装备槽可检查或卸下。若目标已有卡，正式 UI 应先预览被替换卡退回卡库及预算差，再确认替换；研究稿点击槽位即替换，操作后文字提示原卡退回卡库；先预览再确认与拖放属于后续交互实现。唯一资产已在其他槽时定位原槽，不复制第二份。更换英雄降低预算时显示超出量与受影响槽，允许降档或卸卡，不静默修改配置，正式开战校验必须拒绝超预算。

## 6. 消耗卡条件与状态

消耗卡由战前条件控制、战斗自动执行。详情显示“默认条件”或“自定义条件”，编辑入口仅在准备阶段出现。默认值照抄该卡原文，玩家无需先编写规则才能理解卡的预期用途；默认＋可编辑仍是当前卡表提案，需与旧框架议题统一。

条件编辑器属于后续实现设计：打开时保留当前条件，选择系统实际支持的观察对象、状态 / 事件 / 时间及参数，给出一句自然语言预览。保存只在校验通过时替换当前条件；取消保留原值；“恢复默认”恢复原卡条件并允许取消。修改触发条件不修改效果对象、持续时间、次数、伤害和内置冷却，也不能给不支持的条件生成伪配置。服务端确认前显示“提交中”，失败保留草稿和旧生效条件。研究稿不宣称编辑或持久化已实现。

后四阵营按基础卡表 §1.5 当前提案说明，不能无条件覆盖保留的元素原稿：

| 条件类别 | 当前结算解释 | UI 必须区分 |
| --- | --- | --- |
| 时间 | 第 t 秒起每 k 秒尝试，按卡面周期；如 5 秒起每 12 秒为 5 / 17 / 29 秒 | 显示首触发与周期，不能把所有卡统一为每 12 秒；红酒为 14 秒，唤兽肉干为 20 秒 |
| 状态 | 低血 / 低蓝按各单位自身上限，冷却结束时仍满足可再用 | “等待状态”与“冷却中”不同；不要求跨阈值的新事件 |
| 事件 | 施法、承伤、阵亡、印记击杀等成功触发后同卡 12 秒内置冷却 | 冷却结束后等待新事件，不补发冷却期间事件 |

每卡每场次数按装载 Lv1 / Lv2 / Lv3 为 1 / 2 / 3，后四阵营当前采用**全队共享**；多名单位同时满足只扣一次，不按受益人数扣次数。触发观察中的“任一友方英雄”仅看存活上阵英雄本体，受益仍按卡面。共享计数与旧框架各自计数的最终统一是开放决策，不能隐藏冲突。

同卡同效果不叠层，再触发刷新持续时间；护盾刷新为本次数量，不累加。次数扣完不清除已产生的持续效果。例如样例“剩余 0/1，烈酒生效中，剩余 6 秒”应同时显示；只有效果到期后才变成“次数用尽，效果结束”。立即效果、召唤物、永久死亡印记各自依原卡生命周期说明，不能一律画成限时增益。不同卡的叠加上限单独处理，不由 UI 自行推导。

## 7. 场地总览与共鸣领域

场地层覆盖全战场，不锚定或跟随携卡英雄，没有场地半径、落点和技能施放者。不同场地卡独立共存，已生成后持续至本场战斗结束，携卡者阵亡、复活、换人均不使其失效。它们不是召唤物，不占单位数、不被驱散，也不归入携卡英雄的技能伤害 / 治疗收益。

战斗状态用统一“场地”栏显示卡名、装载档、效果和“持续至战斗结束”。携卡英雄仅作为来源槽位索引，不能成为效果归属标记。可显示场地共 6 张、共鸣计数 5/5；总场地最多受 8 个通用槽限制，共鸣计数封顶 5 不代表只能装 5 张场地。

| 共鸣领域 E-f3 | 当前确定口径 |
| --- | --- |
| 身份 | 元素基础场地卡，通用槽，无轴图标；COST 分档未定，取代旧灼热之地 |
| n | 全队已生效场地卡张数，含本卡，按张数不按等级，上限 5 |
| 属性 | Lv1 +6n、Lv2 +10n、Lv3 +20n 全属性；Lv3 属性封顶 +100 |
| 结算时点 | 准备阶段装卡、换卡、改档、换人即时重算；开战快照冻结 |
| 属性对象 | 只对上阵英雄本体施加；满编为 8 人，形态 / 幻象 / 召唤物不再额外施加 |
| Lv3 额外条款 | 出场且携带场地卡英雄的主属性合计 ×0.1%，500 点封顶 +50%；全才取力量 / 敏捷 / 智力最高值 |
| 防重复规则 | 合计不含本卡 +20n；增幅只施加其他场地效果，本卡 +20n 不受增幅；一次计算，不迭代 |

详情分开呈现“属性贡献”和“Lv3 其他场地增幅”，Lv1 / Lv2 后者明确写“Lv3 解锁”。研究稿可显示原文或明确标注的布局样例，不能用不完整英雄数据计算并冒充真实快照。

恐惧领域每 5 秒降低 2/4/6 力量、血池每 3 秒降低 20/30/40 生命上限、荆棘丛林每秒降低 0.5/0.8/1 全属性，均逐次累加、无累加上限并可致死。详情保留“每次增量”“逐次累加、可致死”，不错误显示成一次性固定减值或保底 1 生命。

## 8. 卡背、报价、获取与熔炼

报价沿用原卡背，购买前仅露出允许的阵营徽章、类型图形、价格与购买额度；不显示卡名、等级、数值或轴。名称不得藏在悬停提示、可访问名称、搜索结果或翻牌预览里泄漏。未知卡的可访问名称可写“第 2 个报价，元素，消耗卡”。图鉴公开全部设计与报价隐藏具体抽中身份可以同时成立。

正式报价流程为准备阶段查看 5 张背面 → 选择报价 → 确认价格与剩余额度 → 提交购买 → 服务端成功后揭示身份并更新资产。失败保留卡背和原余额；重复点击提交期间禁用，重试不得重新抽卡。每波英雄购买与卡牌购买合计最多 3 次，未购报价下波作废。研究稿卡背页仅展示原背资源，不实现翻牌购买。

重复卡获得后用短反馈说明“拥有 Lv2→Lv3，仍按 Lv1 装载”，不生成第二个槽位资产。基础卡 Lv3 后再获得同名份数走本局永久加值结构，属性口径及上限仍未定，不能把旧 +1 智力、99 上限写成最终收益。专属卡溢出保留为可熔份数。

正式熔炼流程为筛选未装备专属卡 → 选择同阵营份数 → 预览熔炼前后份数 / 等级 / 阵营点数 → 二次确认 → 成功后更新。每份换该阵营 1 点，3 点兑换同阵营任意一份基础卡；例如 Lv2 专属卡熔 1 份后成为 Lv1 并得 1 点。基础卡不可熔，已装备专属卡须先卸下，不能兑换专属卡或跨阵营支付。兑换已有卡增加份数，兑换新卡才新增资产；最后一份熔掉会移除资产，应在确认中明确。研究稿不模拟熔炼结果。

## 9. 战斗、退卡与错误反馈

正式开战从准备配置校验到快照生效应是一次完整事务；失败保留准备阶段配置，不扣命、不留下部分卡效果。战斗页可检查说明和展开状态，不显示可执行的装备、调档、熔炼、条件编辑或手动消耗按钮。研究稿切换“战斗状态”仅切换只读布局，所有计时和状态若为样例必须可见标注，不宣称正在模拟战斗。

战斗结束清除本场效果，消耗卡回到卡库，资产和拥有等级仍保留；次数在后续战斗按装载等级重新建立。换人 / 卖出英雄也应退卡，不能吞卡或静默转移。**卡库已满时的退卡，包括战后消耗卡回库，仍未决定采用阻止、临时超额还是其他方案。** UI 必须把退回数量与容量压力呈现出来，不擅自定为自动丢弃、自动熔炼或永久占槽。

| 场景 | 用户可理解的反馈与恢复路径 |
| --- | --- |
| 未拥有、越级装载、槽型不符 | 就地说明原因；图鉴可继续查看；定位正确通用槽或已解锁档 |
| 唯一资产已装备 | 显示现有携卡者与“定位槽位”，不生成副本 |
| 超预算或换人降预算 | 显示已用 / 上限与超出量；定位卡槽，提示降档 / 卸卡；不开战 |
| 未装备卡库已满 | 显示 24/24 与受影响退卡数；说明容量方案待定；研究稿若阻止操作须标为演示限制 |
| 无搜索结果 / 尚无资产 | 分别提供清除筛选 / 获取说明，不混为加载失败 |
| 金币不足 / 购买额度耗尽 | 按钮带文字原因与差额 / 已用次数；不扣费、不提前揭名 |
| 熔炼份数不足 / 卡已装备 / 阵营不符 | 保留选择与输入，指出对应原因；不做部分扣除 |
| 条件无效 / 默认语义尚未明确 | 定位问题字段，保留草稿；原文仍可查阅，不自动生成条件 |
| 阶段已变化或请求过期 | 提示“已进入战斗，本场配置已冻结”；同步权威状态后保留只读查看 |
| 请求失败、重试、数据缺失 | 保留最后有效状态；按钮恢复，说明可重试；缺数据写“原文待校对”，不展示猜测值 |
| 效果次数已用尽但持续中 | 同时显示 0 次与生效剩余时间，不置灰整个效果 |
| 携卡者死亡 | 保留已生效增益 / 场地和原到期时间；复活不刷新每场次数 |

## 10. 尺寸、文字与可访问性

下列尺寸为浏览器研究与后续原生适配的设计基准，不是对已实现页面的测量结果。以 1440×900 检查主布局，1920×1080 放宽网格，1280×720 保留核心操作；更窄窗口折叠筛选、把阵容和详情改为纵向分区。不能靠整体缩小文字塞进屏幕。

| 元素 | 建议尺寸 / 行为 |
| --- | --- |
| 页面间距 | 外边距 24 px，区块 16–24 px，卡间距 12–16 px，8 px 基础节奏 |
| 网格卡 | 宽 176–208 px，高约 264–312 px；保留既有卡背长宽比，不拉伸原图 |
| 详情面板 | 桌面宽 340–400 px；窄屏占一整行，长文滚动且标题与关闭入口可达 |
| 阵容槽位 | 8 英雄可用两行，每英雄明确分组两个槽；交互热区至少 44×44 px |
| 字号 | 页面标题 24–28 px，卡名 17–20 px，正文 15–16 px，辅助 13–14 px；关键效果不低于 14 px |
| 行距 | 中文正文 1.5–1.7；三档效果分段，避免将长条件压成一行 |
| 焦点与对比度 | 正文对比至少 4.5:1，大字与非文本控件至少 3:1；焦点环至少 2 px，选中态不只靠颜色 |

阵营颜色保留原卡背体系，新增卡面以边框、徽章和文字共同标识。类型以独立形状和名称区分。红色错误必须附文字，灰色未解锁必须可读。尊重减少动画偏好，不以闪烁表示冷却；卡背揭示动画属于后续设计且不能挡住结果阅读。

Tab 顺序遵循页面视觉次序；卡片、筛选、档位、槽位均支持键盘聚焦，Enter / Space 执行与点击一致的操作。弹窗打开后焦点进入，Escape 取消并返回来源；详情关闭恢复原选中卡焦点。悬停说明也能通过聚焦与点击获得，不能把规则只藏在悬停里。点击装备是基础路径，拖放即使后续增加也必须有等价键盘路径。

## 11. 源文保留与不确定性

本轮后四阵营重设计不改动保留的元素 20 张和后四阵营 16 张场地原文。UI 优化可以分段、补标签和解释当前明确规则，但不得暗中重写数值、补启动条件或修正机制。

| 原文情况 | 展示方式与边界 |
| --- | --- |
| 元素充能有④标签但条件为空 | 展示原技能增强 +4%/+7%/+10%；不补充“达到若干层” |
| 成长等表格字段留空 | 保留效果原文，缺字段不编造条件或轴 |
| 火盾 400 范围、爆裂符文 500 范围 | 展示原范围，中心 / 周期等未明确处标“待校对”；不能套用场地全场规则 |
| 醒神咖啡 / 爆裂符文的“全队首次” | 保留原条件；不擅自改成任一存活英雄、不自动套后四阵营重复规则 |
| 冰激凌持续时间、火龙果灼烧细节等 | 保留已有数值与时长，只标实际缺失语义，不代填默认 8 秒或 12 秒 |
| 风暴场的技能实例范围 2000、黎明之墙的随机墙体 | 场地层仍全战场，实例几何与生成原文保留；不把技能范围误做场地半径，也不承诺所有目标每次必受实例命中 |
| 兽穴的“大野 / 大野 / 远古”等保留效果 | 三档原文照录，单位池、寿命等未写明之处不自行生成 |

仅凭保留原文不能保证可直接执行。研究稿应让玩家看到“源文待明确”的具体项，并可回查基础卡表；不能把这些不确定条件做成看似已生效的战斗逻辑。
