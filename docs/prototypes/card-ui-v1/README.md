# 当前卡牌 UI / UX 设计稿 · UI99

用浏览器打开 [index.html](index.html)，无需启动服务、安装依赖或连接网络。完整规格见 [CARD_UI_UX_V1.md](../../CARD_UI_UX_V1.md)。这是可点击的设计稿，原生 Panorama 仍使用已有 UI98，不代表卡牌运行时已经接入。

页面提供三个场景：准备构筑、战斗状态、既有卡背。准备构筑可切换本局卡库与完整图鉴、筛选阵营和类型、搜索名称/效果/ID、查看三档原文、调整装载等级、点击通用槽装卡或替换、从详情卸卡，并检查超预算状态。图鉴只读。战斗页是静态状态示例，不执行计时或真实效果。

示例持有 16 张唯一基础卡，均拥有 Lv3，初始 4 张装备、12 张在卡库。8 位英雄均为 Lv8，示例预算 64。所有费用暂借普通档 1/5/10 演示，**不构成任何卡的正式 COST 分档**。调档会更新示例费用与消耗次数，卡面仍保留三档完整原文；未实现任意复合效果的逐档数值解析。所有操作仅在本页内存生效，刷新重置。

卡牌名称、ID、轴、默认条件和效果来自 `BASIC_CARDS_V1.md`，保持元素与场地原稿。更新卡表后，从仓库根目录执行：

```sh
python docs/prototypes/card-ui-v1/build-data.py
node --check docs/prototypes/card-ui-v1/data.js
node --check docs/prototypes/card-ui-v1/app.js
```

五张卡背直接引用仓库 `pics` 原图，文件名及阵营映射沿用 [CARD_FORGE_UI98.md](../../CARD_FORGE_UI98.md)。没有重绘、裁剪或覆盖原文件。原图按仓库现有规则不随 git 上传；新的工作副本需恢复 `pics` 中的五张资源。缺失原图不影响构筑页与图鉴使用。

本轮 Chromium 离线浏览器检查已通过：100 张卡与 45/35/20 分类、阵营与搜索筛选、图鉴只读、8 英雄双槽、装卸与替换的唯一资产守恒、三档 COST 和共享次数切换、超预算阻止及恢复、1920/1440/1280/390 宽度无水平溢出、零次数持续效果示例、五张原卡背正常加载，以及无页面脚本错误。截图检查覆盖准备构筑和战斗状态。上述验证不替代原生 Panorama 编译、渲染、服务端事务或战斗验收。

当前原型没有购买、熔炼、触发条件编辑、拖放、专属卡效果和持久化。这些流程的 UI 设计详见规格；未定的费用和满库政策继续由既有 beads 议题跟踪。
