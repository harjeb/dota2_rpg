# UI41：首关启动、下一关后台预加载与失败重开

运行版本 `rpg-runtime-v41-20260912`。开场只同步预加载第一关和通用必需资源；第一关敌人生成完成后，后台提前加载第二关，此后逐关提前加载下一关。生命耗尽后的“再来一次”与最终通关一致，均从第一关开始。

## 加载范围

此前 `Precache` 遍历全部 30 关，共调用 76 次单位同步预加载、61 次物品同步预加载。当前数据的启动集合是：

- 通用物品 4 种：低级／高级经验卷轴、不朽之守护、奶酪。
- 后续英雄与装备在所需关卡的异步队列中准备。玩家招募和技能测试继续使用各自已有的异步流程。

这是同步 API 调用数量从 **137 降至 7**，不是加载时间缩短比例。此前约两分钟的完整加载没有可用实机分段计时，不能将其全部归因于 Lua 预加载。`MinimalPrecache` 未改动。先前 Workshop 缓存版本与传输记录见 [启动诊断](STARTUP_LOADING_DIAGNOSIS_2026-09-11.md)。

## 后台队列与切关

新增 `battle/stage_precache.lua`，按关卡规划单位和装备，跨关卡复用已准备资源。正常队列一次发起一项原生异步请求，下一项至少经过一次延迟调度；不会在回调栈内连续启动后续资源。只提前请求下一关，首次进入不排队整个三十关。

使用当前原生 `PrecacheUnitByNameAsync` 和 `PrecacheItemByNameAsync`；两者及 `RealTime` 均已在本机 `server.dll` 注册字符串中核实。日志计时使用原生说明为“不随游戏暂停”的 `RealTime`，记录启动总耗时、各同步资源耗时、异步开始／完成／失败和关卡就绪计数。

当前请求优先于后台请求；快速切换时，最新请求优先处理。已经发出的原生请求不能取消。资源异常、回调失败、缺少 API 或超时不会退回同步加载；前台显示准备失败并提供重试。超时后的原生操作仍可能在底层继续，过期回调不会完成新的请求，重试可能与旧底层操作短暂重叠。

切关的结算流程保持三秒展示，若资源未完成，准备界面显示等待并禁止开战；就绪后才替换敌人。战斗就绪还校验**实际生成成功的敌人属于当前关卡**，防止旧阵容被当成新关卡。

待处理生成请求校验关卡、结算编号、规则代次与技能测试状态。进入／退出测试清理旧生成意图；仅取消尚未进入的测试不改变正常关卡请求的结算编号。缓存本身继续保留已加载资源。

所有敌人生成入口都捕获原生生成／准备异常，清理已创建但尚未登记的单位，并允许再次准备。生成返回未完成／失败时，兼容层不把新关卡配置绑定到旧敌人。点击“重试资源准备”只准备资源与敌人，不自动开战。

## 失败后从第一关开始

生命耗尽或最终通关时，按钮统一显示“再来一次：从第一关再战”。服务器无条件选择首关，恢复五条生命并重置刷新次数、卷轴购买计数。沿用既有英雄养成、装备、规则和金币保留行为；尚有生命时的普通失败流程不变。
