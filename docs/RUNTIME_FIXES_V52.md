# UI52 条件设置窗口精简

## 用户可见行为

- 选择技能时，把该技能原有推荐列表中的第一套方案自动填入条件草稿；保留“应用 / 取消”流程。取消不改变原规则，再次打开已有规则不覆盖玩家的修改。没有推荐方案的动作使用基础配置。
- 删除“刷新技能能力（保留草稿）”和推荐 / 关闭 / 优先队友 / 允许自身方案按钮；移除当前技能能力与推荐预览，保留错误提示。
- “清空全部条件及开关设置”改为“重置”，使用红色背景，固定在窗口右上角。重置清空条件并恢复动作默认值，支持开关的技能回到开启状态；仍需应用才能保存。
- 删除候选单位类型与目标模式控件。程序使用原生支持的候选类型和自动施法模式。
- 条件状态仅支持下拉选择，不再提供 modifier 代码输入。已保存但当前不可用的状态显示为不可选，并通过错误提示要求替换或移除对应条件。服务端返回完整的有界已观察状态列表，取消原先只返回前 32 项的截断；已拥有的缩地、践踏和地雷滚滚技能在首次施放前也会提供已明确声明的关联增益。
- 开关与原生自动施法合并为“开关技能”，只提供开启 / 关闭，默认开启。程序按技能原生能力选择 `desired_toggle_state` 或 `desired_autocast_state`；普通技能不显示无效开关，明确保存的关闭状态可往返恢复。
- 删除状态控制策略、最短保持时间、施法变体和未验证状态确认。保存使用固定策略、默认变体，避免旧的隐藏设置阻止新窗口应用。保存前再次读取当前技能能力，补全新获得的原生开关、清除失去支持的状态；原生类型改变时保留玩家选择的开启或关闭。
- 持续移动的“关联原生增益”只保留“自定义”，其状态从下拉列表选择；不再提供原生 modifier 输入框。缩地、践踏、地雷滚滚移动预设仍可使用，自动保留关联原生状态与触发技能。
- 新持续移动规则和三套移动预设均默认开启“目标失效后重新选敌”“循环移动”。Lua 合同同样补全缺省值，已有明确关闭的设置保持关闭。

## 验证与部署

`python scripts/test-all.py`：87 / 87 离线测试组通过。覆盖推荐草稿到应用 / 取消 / 重开、条件状态下拉、原生 Toggle / Autocast 开关往返、失效状态提示、只读与过期编辑保护、持续移动默认值与显式关闭。

原生资源编译器成功编译 XML、三个 JS 和 CSS；九个源码文件同步到本机 Dota addon，并核对 SHA-256。部署记录见 `tests/results/ui52-condition-settings-deploy.json`。持续移动合同同时更新兼容 overlay。

`docs/CONDITION_SETTINGS_UI_REFERENCE.html` 已更新至 UI52，保留全部 85 个条件说明、搜索和打印功能，并通过 HTML 结构、链接、菜单对照与脚本交互检查。

本轮没有启动 / 停止 Dota、执行游戏命令或截图；游戏内实际布局尚未验收。没有修改创意工坊缓存包或发布远端，普通客户端需要重新打包上传并获取 UI52。
