# v22：原生物品栏右键出售

2026-09-09，界面版本22，运行标记 `rpg-runtime-v22-20260909`。

用户明确要求在原生物品栏右键出售，而不是必须到项目装备面板操作。

发现并修复：原先 SELL_ITEM 在携带来源单位时直接以该单位校验持有关系。如果原生 HUD 指令以玩家主英雄小精灵为来源、被查看装备实际在上阵或待命英雄身上，会拒绝出售。v21 仅处理没有来源单位的情况，未覆盖这条路径。

v22 的出售分支按确切物品实体查找当前合法持有者，重新绑定合法载体的玩家归属并将订单 units 设置为实际持有者；接受正确的原持有者、主英雄或无单位形式。保持引擎原生 SELL_ITEM 执行，不转为面板操作、不手算退款、不改购买时间或购买者。标记库存/钱包需要刷新。原生出售许可与原生退款仍由引擎决定。

保留正确玩家身份、准备阶段、合法来源载体、单一来源、真实物品与0–14槽位持有关系检查，购买扣款尚未核对时仍阻止出售。拆分逻辑不改变，项目出售按钮保留为备用入口。

`tests/shop-state.test.lua` 新增原生右键指令测试，覆盖主英雄502发起而装备属于英雄501、正确持有者发起、订单实际持有者重写、外国玩家拒绝与战斗阶段拒绝；已有无单位指令测试保留。完整 run_checks.py 与 verify-addon.ps1 通过。

现有 console.log 只有旧版本购买记录，没有 SELL_ITEM 出售记录，因此不能把本次静态确认的缺陷断言为用户现场的唯一原因。没有启动、关闭 Dota 或截图；真正的右键菜单及退款还需要用户重载界面22后验证。若菜单根本没有“出售”或引擎拒绝执行，需要用户反馈该具体表现，而非声称仅修改过滤器即已实机验证。
