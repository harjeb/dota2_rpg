# UI59：撤销导致商店一开即关的按钮接管

用户实机反馈 UI58 打开商店后立即关闭，无法购买。UI57 的自动选中小精灵及物品交付此前已由用户确认可用。

## 修改及证据

删除 UI58 的 `wireNativeShopToggle`、按钮缓存及轮询绑定调用。插件不再修改原生 `ShopButton.onactivate`，也不再派发 `DOTAShopHideShop` 或 `DOTAHUDToggleShop`。原生按钮独自处理开关；插件只观察 `DOTAHUDShop.ShopOpen`，同步购买目标和临时选择小精灵。

保留独立的 0.15 秒关闭后还原：仅在已观察到关闭、等待结束后仍关闭且头像仍是小精灵时还原。事件以实际根面板状态为准，观察到重开、阶段切换或新局会作废旧还原。此路径不主动发出关闭命令，回归验证开店、连续轮询和购买余额更新期间不会执行还原。

UI58 的测试只模拟了替换后的脚本回调，没有模拟原生默认动作与脚本回调都执行的风险。UI59 将两者分开，覆盖两种顺序、有/无原生开合事件及 HUD 重建。把已提交的 UI58 源码在内存中代入新测试，会触发 `one native opening click must stay open after activation` 失败；UI59 通过同一测试。这证明新回归能拦截该风险模型，不代表已经追踪到了引擎真实的事件调用顺序。

## 验证与部署

- 完整离线套件 87/87 通过；最终新增的即时打开断言也通过 HUD 针对性复测。购买目标、原生金币标签、改选/重开/阶段/新局及关闭后还原回归通过。
- 编译与本机部署结果见 `tests/results/ui59-shop-close-deploy.json`、`tests/results/ui59-shop-close-workshop.json`。开发插件与两份本机 Workshop 包更新为“界面版本 59”，原文件有备份。
- Lua 购买及交付代码未修改。未启动/停止 Dota、执行游戏指令、截图或上传远程 Workshop。
- 实机验收跟踪 `dota2_rpg-6vl4`：重载 UI59 后确认商店保持打开、购买交付、关闭及英雄还原。此前“需要两次点击关闭”是否仍存在需用户确认；撤销按钮接管后不再宣称强制一次点击关闭。无事件且重开再关闭全部发生在轮询间隙内的过渡不可由轮询完整识别，快速操作也需实机观察。
